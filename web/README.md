# RouteWeaver web console

Task-oriented React application using official shadcn/ui (radix-nova), Tailwind semantic tokens, TanStack Query and ReactFlow. The personal workspace is separate from administration. All mutations use the real control-plane API: there is no frontend fixture fallback, simulated persistence or fabricated application status.

## Local development

From the repository root, start `./scripts/go.sh run ./cmd/control-plane --demo --listen 127.0.0.1:8080`. In `web/`, run `npm ci` then `npm run dev`. Vite proxies `/api` and `/feed` to the local control plane. The explicit demo server is ephemeral, loopback-only and prints its synthetic login credentials. Do not use demo mode for deployment.

Production assets are generated by `npm run build`; use the root deployment instructions to serve the built application with its API on the same origin. Cookie sessions and CSRF tokens are used by default. The local bootstrap bearer-token option stays only in memory. Credentials and backup passphrases are not stored in localStorage.

## Verification

- `npm run typecheck`: strict TypeScript check.
- `npm test`: pure model regressions and real React component user tasks in jsdom.
- `npm run test:api`: Playwright **request** tests against a fresh Go demo server and Vite, not mock HTTP fixtures and not a rendered browser.
- `npm run test:browser`: desktop/mobile/keyboard user journeys in Chromium.
- `npm run test:e2e`: both Playwright projects.

Current verification is source-bound and recorded in [WIP47 final verification](../docs/verification/WIP47-FINAL.md). Native browser automation was blocked before UI assertions by this execution environment; the supported cloud browser was used separately for actual desktop and bounded iframe-viewport review. These are distinct evidence, not an automated-browser pass or mobile-device certification. No browser security was disabled.

Official registry components live in `src/components/ui`. Application-specific form, confirmation and task-lifecycle composition lives in `src/ui-patterns`; the mature `rc-field-form` package retains nonvisual validation/state semantics. Retired Ant Design and bespoke presentation styles are removed. Registry adaptations and minimal accessible semantic-token adjustments are documented in the migration record.

## Important boundaries

- A source/profile list is a masked summary. Editing or copying explicitly fetches its authorized `/reveal` response first. Failed imports keep the draft and prior successful snapshot.
- Preview responses, collection stages, template update reviews, resource inspection and server application reviews are fenced against changed inputs. Publishing and applying are explicit operations, separate from saving.
- Profile editing uses stable endpoint/group/resource references. A separate native JSON/YAML editor preserves raw drafts, binds the exact client version, and previews supported native field/rule composition. Portable IR editing remains separate.
- Existing-output update reviews send the output identity to retain its established names and exact client target. The returned digest is required by the update modal. Changed inputs cause a stale-review rejection and require another preview before republishing.
- Ordered server paths compile separate per-instance programs. The graph is not a client-chain preview. Principals, TLS material and destination exceptions survive topology editing. Managed user entry rotation uses the published-route principal API, never the legacy manual editor.
- Queued server configuration is not labeled applied. Actual application status is read from the instance observation API. Saving service limits alone does not claim runtime enforcement.
- User groups select one service by priority without stacking quotas. Individual overrides distinguish inherited values, explicit zero and empty route denial. Service/group/user changes review affected users before an exact-change, revision-bound apply; blockers and stale reviews retain inputs. Online IP unions, account-global logical stream caps and per-entry rates are separate, and current admission counts are dated leases rather than device counts.
- Subscription-domain changes save a draft, verify public HTTPS and the same instance, then activate explicitly. Failed/stale changes preserve the current origin and typed input. This does not alter DNS, TLS, console origin or credentials; old URLs still depend on their existing routing.
- Private rule files are explicitly uploaded or fetched and accepted as immutable owned versions. Profiles reference the accepted manifests, not file bodies; outputs with local rule files download an authenticated ZIP bundle rather than a broken bare subscription/QR link. Replacements do not mutate already-published bundles.
- Managed public credentials are unavailable until the server confirms the pinned applied deployment. Synthetic tests verify pending states, not live VPS deployment.
- Full backups download encrypted files. Preview/restore upload the encrypted File directly using ordered multipart fields, without a base64 duplicate, up to a 1 GiB client ceiling (the operator may set a lower server limit). Restore requires a fresh authenticated preview and explicit typed confirmation, stages a new database and never switches the live store.
- Fleet changes use explicit grouped/tag-filtered targets and stages, an exact-input review fingerprint, current per-target outcomes and failure-only retries. Installing a catalog version is distinct from running it; later stages require server-confirmed prior outcomes.
- Diagnostics explicitly choose direct server egress or an already-applied managed connector path. Managed tests begin at the entry core and cover configured transit/exit, not public entry TLS or client admission. The backend pins all hops; changed paths cannot claim success. Uploads require a dedicated PUT sink. Payload is counted once, not the aggregate per-hop wire or supplier-billed traffic; missing timing/cost remains unknown.
- Announcements and account alerts remain in-app. Notification settings do not send on save. Explicit test sends display the returned channel state; external acceptance does not mean delivery or reading.
- Host details read real CPU, memory, load and selected NIC observations. Unknown values stay unknown. Supplier quota is independent of user usage; statements and digest-bound NIC baselines are explicit operator inputs. Unlimited suppliers require no invented cycle. Provider alerts use the configured observation source, never a fabricated balance.

The API contract is represented in `src/types.ts`, `src/api.ts`, and task-specific adapters. Navigation guards protect unsaved drafts, stale async results cannot replace newer inputs, and ordered editors provide keyboard controls alongside drag operations.
