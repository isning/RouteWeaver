# Service-rate draft native sampler

Follow-up to `SERVICE-RATE-DRAFT-CONTINUITY-2026-11-11.md`, source `bebe37d`.
This sampler is deliberately separate from the accepted eight-case policy
inventory recovery sampler.

## Public journeys

`service-rate-draft.ui.spec.ts` defines four cases: visible `-` and collapsed
`1e`, each at 390×560 and 1440×900. The real App, private session boundary,
StrictMode, guarded service editor and confirmation components remain intact.

A synthetic saved service opens at 250000 bytes/second (2 Mbps). Native keyboard
input replaces it with incomplete text. Preview must reveal/focus the rate,
retain that text, show its validation error and send zero preview requests.
For the collapsed case, Preview must reopen the limits accordion naturally.
Cancel must protect the unfinished draft; Continue keeps it. Only the visible
`-` case establishes a raw-only edit: typing `1e` passes through a valid `1`, so
that case also changes the accepted numeric rate before the incomplete suffix.
A subsequent
`+03.000` correction must survive collapse/reopen exactly. Closure is settled
and the rate control must be absent even from hidden-role queries before
reopening. It must then produce one
synthetic preview for 375000 bytes/second with the opening precondition. The
review after-value cell must equal exactly 3 Mbps. No confirm/apply/save action is invoked.

Existing scope remains deliberately bounded: no latest-version adoption,
collision restart, explicit input discard, backend revision enforcement or
real saved rate change is claimed by these native cases. Those related DOM
checks are separate evidence.

## Isolation and artifacts

All API GETs are exact allowlisted synthetic responses. The only accepted POST
is the exact preview path with the complete expected synthetic change and
precondition; its response is fulfilled in the browser route, never forwarded.
Malformed or different preview bodies, all other writes, unknown API reads,
metadata-bearing requests and external HTTP origins are rejected. Only bounded
static document/module/font paths and Vite query metadata can reach loopback.
HTTP interception does not cover WebSockets, and is not claimed as network-wide
isolation.

Diagnostics store fixed rejection categories and numeric counters, not request
bodies, raw URLs, headers, credentials or page-error text. Validated preview rate
bytes are recorded. Opening read counts are sampled when the editor becomes
ready rather than assuming a single StrictMode transport attempt. Auth and
opening counts must remain unchanged during the editor journey.

Screenshots preserve the original viewport and privacy masks before geometry
assertions. Natural task motion is settled without disabling animations or
forcing focus/scroll. Focus checks require viewport containment, keyboard focus
visibility and center hit-testing. Final-original capture and ledger are attempted
on failures. Explicit phase PNG/JSON and ledger filenames are allowlisted in the
supplemental workflow; arbitrary/private files remain excluded. No images have
been generated by source-only preparation.

## Preparation verification

The proposal was staged outside the checkout while source integration finished.
Strict standalone TypeScript passed and staged Playwright discovery found all
four cases. Focused workflow contracts and clean patch application are checked
before integration. Native execution, pixel acceptance and a full aggregate are
not claimed by these checks. No browser bypass, real writes, deployment or
publication was performed by this sampler work.
