# 备份恢复：操作结果与恢复动作

日期：2026-10-24。候选验证记录；是否合入以集成回执为准。不声称完整产品、全量门禁、原始大备份用例或 Google 水准已通过。

## 问题与决定

网络连接中断不证明恢复没有创建数据库。旧页面将传输错误按普通失败展示，重新校验和重试可能丢失前次结果不明这一事实。

本轮区分三个权威结果：已创建、明确未发布、发布结果不明。成功只接受 HTTP 201、已恢复状态、安全目标文件名与未启用标记；丢失响应、截断正文、失效会话响应和不合约成功均不能冒称失败或成功。明确的授权/输入拒绝保留其原因。四个新恢复阶段错误通过稳定 reason 映射为中文，不匹配英文、不改全局错误处理。

恢复到新数据库不自动切换正在运行的数据。完整成功发生后，即便请求截止时间已到，也不把 nil 结果改成失败。操作和上传预算不变，仅在工作开始前为恢复响应预留一秒写入时间；不能延长已过期写期限。清理、不可中断工作或断线仍可能阻止结果交付，因此预留时间不是交付保证。

## 一套有界的交互模型

- 提交时冻结已校验文件、密码、digest 与确认文字，组件缓存仅存关联编号，不保存秘密。同步所有权保护检查与恢复，不依赖下一帧 disabled。
- 当前结果不明保留对应目标（如已知），清空确认文字并阻止再次恢复。修改、清空、重新校验均不解决它。
- 用户明确确认操作已结束并检查恢复目录后，当前未知转为“此前恢复的人工检查记录”；旧预览失效，需新校验和确认才能新建一次恢复。
- 新未知有自己的目标，不借用旧目标；只有又一次明确人工检查才替换之前的人工记录。状态有界且不丢弃未检查的未知结果。
- 这是页面内人工记录，不是服务端对账、幂等键或持久恢复日志。离开/刷新页面不保留记录，也不提供自动查找未知目标的能力。

## 可复用规则及来源

以下是项目综合规则，不是 Google 或任何官方指南的逐字要求。

1. 先按权威结果分类，再给恢复动作。传输失败不等于业务失败；未知状态不能用普通重试掩盖。沿用 [Carbon 通知指导](https://www.carbondesignsystem.com/building-blocks/core/components/notification/guidelines) 的上下文状态与可行动反馈原则（来源目录 GS-09）。
2. 简短按钮描述真实动作，关键前提放在同一决定区。未知警告只在未知时出现，旧人工记录按需展开，普通成功不携带常驻不确定性说明。沿用 [GOV.UK 界面写作指导](https://www.gov.uk/service-manual/design/writing-for-user-interfaces)（GS-16）与项目内容设计规则。
3. 人工确认、系统验证与业务完成分别命名；清空确认框、消费预览凭据、重新校验都不是对账或幂等。这条来自本次领域建模与反例，不附会为外部标准。
4. 保留“对象身份 + 尝试身份 + 输入版本”关系。响应归属于发出的尝试，而不是到达时碰巧显示的表单；后来的未知不能继承旧目标。
5. 视觉检查和行为检查分开。键盘焦点、窄屏重排参照既有 [WCAG 2.2 固定版本](https://www.w3.org/TR/2024/REC-WCAG22-20241212/)（GS-01）；几张截图或组件测试不代表全产品无障碍合规。

来源目录及原访问日期见 docs/design/UX-GUIDELINE-SOURCES.md。本轮沿用已核验内容，不伪造新的访问日期。

## 证据边界

- 实际 RED：原接口恢复写/读预算无预留；旧候选同轮输入更改导致提交快照不一致；两个检查所有权竞争；四个稳定原因未本地化。
- 新 store 类型在旧源码不存在，只能编译失败，不把它当成物理故障的功能复现。撤回的 seam-only RED 草案未执行。
- 物理文件发布故障与 HTTP 组合证据分开。HTTP 组合用真实加密备份、认证、预览、实际数据库恢复与重放检查，只在最后操作边界注入分类；不称为端到端物理故障注入。
- 首次 Go 聚焦组有一个测试过度断言 DeadlineExceeded：真实 net/http 读截止会取消上下文为 Canceled。修订为原截止不变、Done 且错误非空，不放宽生产预算。
- 第二次测试遗漏显式测试预算，使用默认十分钟等待；环境重启中断。保留原日志，未计为通过或原生超时。最终测试显式三十秒诊断预算，无生产预算修改。
- 浏览器使用真实生产构建与合成 HTTP 结果，验证界面状态/操作/布局；不是浏览器到真实加密恢复的全链路，也没有部署或实时服务切换。

最终逐项结果与截图见本轮验证回执；未运行或失败阶段不能用局部通过替代。

## 实际画面复核带来的收敛

实际窄屏截图显示，大面积“备份验证通过”色块与未知恢复结果竞争，容易混淆文件校验和恢复完成。改为中性的“文件校验通过”，恢复结果独立显示；恢复范围只在区块入口表达一次。技术版本和分类记录数放入“备份详情”，但账号、二次验证、会话和订阅凭据的恢复及撤销复核提示仍直接呈现在确认操作之前。

原生文件控件显示英文选择动作且重复文件名。保留原生输入能力，以中文按钮调用系统选择器，文件名/大小只显示一次；真实浏览器通过键盘激活按钮并接收 filechooser 事件选择合成文件。统计按实际 record.Kind 映射已知产品词汇，不能把 manifest 的身份/凭据总数当成 counts 的固定分类。

实际桌面浏览器还复现了 Ant Design 加载图标进入动作名称的问题。三个异步动作分别保留稳定名称、独立 aria-busy、装饰性隐藏图标。三个专门用例先失败再通过；没有放宽浏览器名称匹配。

已完成局部证据：最终 43 项前端行为/API 检查和类型检查通过；store/HTTP 选定 race 测试通过，其 Go 文件哈希在后续纯界面轮次保持一致。生产构建通过，保留原有大 chunk 警告。浏览器在 1440 与 390 宽度完成成功、丢失结果、人工检查、已知目标不确定、后续授权拒绝的独立状态，且每条路径恰好四次显式恢复提交，无自动重试。

浏览器首轮因合成订阅域名数据类型错误未进入备份任务，第二轮移动通过/桌面因真实加载名称问题失败；原始证据保留。之后通过的运行不抹去这两次失败。截图另保留视口焦点图，完整页面捕获先回到文档顶部，避免固定定位的屏外跳转链接在滚动位置拼接进长截图。
