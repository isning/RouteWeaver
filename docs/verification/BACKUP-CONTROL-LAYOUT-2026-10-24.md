- 原布局 RED：1440px 仅具名宽度断言失败；390px 通过。失败来自真实过宽控件，不是缺少新 class。
- 原有备份 DOM/API 四组 **62/62** 通过；类型检查、生产构建通过。
- 同一冻结绿色源/构建上，受控布局浏览器 **2/2** 通过（1440/390px）。
- 独立真实加密导出→预览→恢复 **2/2** 通过：备份后新 cookie 会话保持有效；真实接口返回 201；只生成新目标库、未切换当前服务；目标与活动库分离，目标权限 0600。未将受控 HTTP 状态冒充这些证据。
- 恢复运行后的源、构建、canonical 源及非生成 Node 依赖字节/模式均未变化；自有进程及私有数据库清理完成。未重哈希 Go 缓存；不作全依赖供应链完整性声明。

## 运行异常与恢复

首次运行在绿色浏览器启动前，复用端口的 bind 探测出现 `EADDRINUSE`；未复用未知监听器。该次完整依赖比较也因 Vitest 写入 `.vite/`、`.vitest-cache/` 生成缓存而失效。原始 invalidated 收据、失败日志及差异保留，没有改写为通过。

经审核后，只续跑未完成的浏览器阶段：先验证完全一致的绿色源/构建，再使用两个不同的新自有 loopback 端口；Node 依赖比较明确仅排除上述两个顶层生成缓存路径。未重复基线、62 项测试或构建。结果为布局 2/2、真实恢复 2/2 通过，收据记录清理与不变性。
