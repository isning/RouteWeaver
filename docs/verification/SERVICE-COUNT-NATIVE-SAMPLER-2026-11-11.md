# Service count-limit native sampler

Follow-up to `SERVICE-COUNT-DRAFT-CONTINUITY-2026-11-11.md`. This proposal is
staged outside the checkout while the caller-owned count fix completes its
integration checks. No production files are changed by the sampler.

## Bounded public journeys

Four cases cover online-IP `-` and connection-limit `1e` at 390×560 and 1440×900.
The real App, session privacy boundary, StrictMode and guarded editor remain
intact. A synthetic saved service has IP/connection limits of 2/10.

Each case distinguishes two boundaries:

- With the control visible, native custom validity must already be invalid.
  Ordinary keyboard Preview must focus it and send zero preview requests.
- After natural accordion closure settles and the rate-independent count control
  is absent even from hidden-inclusive role queries, ordinary keyboard Preview
  must reveal/focus the preserved invalid count and still send zero requests.
  This exercises caller-owned continuity without bypassing native validation.

Cancel must protect the unfinished draft and Continue retain it. Only the IP `-`
case is raw-only: typing connection `1e` passes through the valid intermediate 1.
A valid `+003.000` correction must survive settled collapse/unmount/reopen with
its exact spelling and restored native validity. Its one synthetic preview must
contain exactly 3 for the edited count, retain the other count at 2 or 10, and
carry the original opening precondition. The exact comparison after-cell must
show `3 个` or `3 条`. No Save, Apply or confirmation of a policy change is invoked.

## Safety and evidence

Exact synthetic GET responses supply all state. Only the exact preview POST
with the complete expected synthetic record and precondition is accepted and
fulfilled locally; every other write, unknown API read, unexpected body or
external HTTP origin is rejected. Nothing is forwarded to a real policy service.
Static loopback paths and Vite query metadata remain bounded. HTTP routing does
not cover WebSockets and is not represented as network-wide isolation.

Diagnostics contain fixed rejection categories, counters and already-validated
synthetic count values, not request bodies, headers, raw URLs, credentials or
page-error text. Auth and context-read counts must stay at the editor-ready
baseline; StrictMode opening attempts are not assumed to equal one.

Original-position privacy-masked screenshots precede geometry assertions. Real
keyboard navigation, ordinary native validity and existing finite-motion settling
are preserved; no focus script, forced scrolling, sleeps or motion bypass is
introduced. Geometry checks require viewport containment, keyboard focus, center hit-testing
and the actual settled 3px ring inside every clipping ancestor (the existing
0.5px paint tolerance). Fast keyboard entry during accordion opening remains
unchanged. A bounded passive capture/bubble timeline records only control
categories and numeric input/accordion/body geometry, without moving focus or
scrolling. This reuses the separately reviewed service-rate motion diagnostics. Final evidence and the ledger are attempted after failures.
Only explicit phase PNG/JSON filenames and the named ledger are uploaded.

## Scope and verification limits

This is a bounded native proposal, not a new acceptance result. It does not cover
all invalid spellings, safe-integer boundaries, explicit field discard, latest
adoption, collision restart, backend revision rejection or saved count changes.
Related DOM coverage is separate evidence. Current rate-sampler native outcomes
must be considered before carrying its fixture assumptions into this proposal.
Type/discovery/workflow-contract results are recorded during preparation; no
browser bypass, real write, deployment or publication is part of this work.
