### 本应用历史导航缺陷的具体根因与修复

在本应用实测事件顺序中，Window `hashchange` 的 AT_TARGET 阶段，子组件 `syncScope` 先运行并卸载 dirty 编辑；App guard 随 page 重注册后排在其后，导致未保存状态来不及保护。修复为稳定、提前注册 guard，并通过最新 ref 读取当前状态。自然 Back 与 query-only 取消已据此独立复测，完整对象范围和值保持。

这是一条**本应用及本轮运行的诊断**，不是关于所有事件阶段、所有浏览器或所有 React 应用的普遍顺序规则。新增单元事件覆盖不能替代真实历史导航复测。
