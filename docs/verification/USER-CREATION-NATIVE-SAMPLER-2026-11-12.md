# Add-user receipt recovery native proposal

Two representative real-App journeys exercise the creation intent/read-only result boundary, not Go transactions or durable idempotency. Every creation command is intercepted and fulfilled/failed locally. Synthetic names, IDs and records are never sent to a real backend.

- Mobile 390 light: lose the creation receipt after the fixture records the synthetic user. Hold a matching GET, open the editor's newer Cancel decision, then release the old result. Its consequence text, focused Continue action and editor ownership must survive. Repeat with the real App navigation decision via browser Back, then Stay. A fresh explicit read-only check confirms the user with exactly one POST total.
- Desktop 1440 dark: lose the creation receipt, read back absence, then explicitly retry only the same ID and exact submitted snapshot under `If-None-Match: *`. The locally fulfilled retry closes the task and displays one user. Exactly two POSTs are accepted; absence itself dispatches no write.

Navigation starts on Services, uses the existing mobile-capable navigation UI to Users, and then browser Back while the task is open. No sidebar click through a modal, synthetic hash event or focus-trap bypass is used. Held responses use explicit network gates and response completion, not sleeps. A gate is armed only after genuine Check focus and no in-flight state reads. Its state GET must follow the expected real DOM Check activation, with exactly one new read at that boundary; numeric request-start and click-activation epoch timing is retained. In-flight counting starts before asynchronous observation, and the exact held Request object’s native start time is checked after its response completes, when Playwright populates timing. It must have started at or after the intended activation. Reads without the intended activation fail the gate immediately; completed-request timing additionally rejects earlier starts. Pending spinner evidence does not request global animation settling.

The frozen name/quota, uncertainty and absent-result copy, close/navigation consequences and actionable keyboard focus are checked. Original-position masked screenshots precede geometry; copy and actions must fit their current clipping regions, and action rings retain the 3px bounds. The desktop uses actual persisted root theme preference, not painted classes.

Routes allow only exact synthetic state/auth/catalog GETs and the guarded POST. Command ID format, complete body, same-ID/body retry, absence precondition, JSON content type and synthetic CSRF header are checked without retaining headers or IDs. Ledgers contain only categories, booleans and numeric counters. Other writes, unknown API reads, unexpected payloads and external HTTP origins fail closed. HTTP routing does not claim WebSocket isolation.

Only named phase PNG/JSON and the creation ledger are added to the recovery artifact allowlist, with extra-name/extension/wrong-fixture negative checks. Dynamic Playwright shard discovery must retain exact-once coverage.
