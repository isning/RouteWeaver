# Platform TLS certificates

Ordinary TLS in the listener editor supports choosing an existing platform certificate or uploading a new PEM pair. The listener stores the certificate ID. Forwarding-path saves and exit replacements resolve the endpoint-owned pair into the deployment snapshot and assign package paths automatically. Saved paths that predate endpoint-level certificate selection continue to support their embedded material. Saved valid pairs are listed by certificate name and expiry. Existing certificates embedded in saved paths appear in the same list.

The certificate catalog is restricted to administrators and returns metadata only. Selecting a certificate sends its ID. The server copies the corresponding pair into the destination draft and retains it in the encrypted certificate catalog in the same transaction. Existing deployments retain their certificate snapshots until they are edited and applied. Publication still verifies the exact packaged files, certificate validity and the configured names.

The focused API test covers legacy material discovery, authorization, a missing certificate, successful reuse, endpoint-owned certificate precedence and summary redaction. Browser component tests cover listener selection, legacy file upload and the separate REALITY fields.

The ordinary TLS editor can fill SNI from an exact DNS name in the selected certificate. Wildcard entries remain available through concrete hostname input. REALITY keeps the listener's client SNI and the path's handshake target, accepted names and private key distinct. Explicit website presets fill the path target, port, and a matching accepted name. The editor shows a mismatch if the listener publishes another SNI. These are form presets, with no target probes or live handshake acceptance implied.

New REALITY listeners can save their server security settings in endpoint inventory. The editor applies a hostname preset to the handshake and client SNI together, generates paired X25519 keys and a random Short ID through an administrator-only action, and supplies the endpoint-owned material to the saved route. Legacy path-owned settings remain editable. Generation and save do not contact target sites or claim network reachability. The API verification covers generated key matching, endpoint and draft validation, authorization and redacted summaries.
Local Chromium exercised the REALITY form at 1440 px and 390 px against the existing preview core. Both widths selected a site, filled SNI, and generated a real key pair through the control plane. The browser check did not save the test listener or activate a server configuration.

The listener editor groups the handshake target and accepted names, the key pair and its action, and the Short ID fields and generators together. Only stock Xray offers additional SNI entries. Short IDs can be entered or generated independently of the key pair. A focused browser component test checks that both lists survive closing the advanced section and saving the listener. The expanded website presets remain unverified candidates.
