- **Both journeys then sample Services:** search `Plan`, advance to page 2, open Plan 10 and keyboard Cancel as a connected-opener comparison. Return must prefer that original Edit button over the fallback. This is two composed journeys, not a Cartesian inventory/theme matrix. Nodes, routes, Services desktop empty clearing, Users mobile empty clearing, and dark mobile are not sampled. ## Read-only fixture and timing ownership

The real App/session boundary/StrictMode runs against exact locally fulfilled synthetic GETs. Every write, unexpected API route/query, non-allowlisted static request and external HTTP origin is rejected. HTTP interception does not claim WebSocket isolation. No original request headers, credentials, IDs, URLs or bodies are saved. The request ledger contains only numeric counters/timestamps, booleans, null timestamp markers and fixed viewport/theme/inventory categories.

The one held read can be armed only at an idle service-read boundary. The intended toolbar Refresh has real keyboard focus first. A passive capture-phase public DOM listener records only activation time and trusted/keyboard booleans. Exactly one trusted keyboard activation must precede the request. The gate is consumed synchronously by one Request, and a dedicated claim marker is set before any awaited DOM observation. Every non-gated service read after that claim is rejected, including one arriving while activation evidence is being read. Before release, the newer editor and focused field are observed and no held response has been delivered. After release, response completion and native start timing are matched to that exact Request object, not merely the same URL. The start must follow the recorded activation. This assumes Chromium exposes Request timing and `performance.timeOrigin + performance.now()` in comparable epoch milliseconds in this one browser context. The check allows equality at the clock's resolution but no negative tolerance, arbitrary rounding, mocked clock or automatic retry. A clock-resolution/order failure must be investigated on the native runner rather than silently accepted. One additional service read, one held/delivered response and no new authentication read are asserted.

Guarded editor reads use only the exact synthetic Plan 10 endpoint. Each of the two explicit openings owns a separate fixture epoch, admitting one request plus at most its one StrictMode effect replay (one or two total attempts). The ready name field closes that epoch. Further reads, requests outside an opening epoch, a third attempt or a different target are rejected. Both epochs must reach readiness, and the opening-read count must stay unchanged across inventory reconciliation and Cancel. This bounded replay allowance is not permission for transport retries or arbitrary duplicate reads. No test hook, script-driven focus/scroll, forced click, synthetic history event, timer override, disabled motion, increased timeout or sandbox workaround is used.

## Original-position evidence and privacy contracts

Eight explicitly named phase PNG/JSON pairs plus one named request ledger are allowlisted. Captures retain the masked original viewport before passive geometry/assertions. The pending spinner is captured without trying to settle infinite motion. The final original is attempted on failure before abandoned reads are released. Failure evidence is not repaired by scrolling or moving focus.

Checks cover actual focused element, `:focus-visible`, positive viewport bounds, hit testing, 3px ring and ancestor clip containment (the existing 0.5px fractional tolerance), page horizontal overflow, and persisted/painted theme. SearchField's official InputGroup wrapper paints its ring, so the focused input and actual ring carrier are measured separately. No raw DOM text, field value or computed CSS string enters these geometry records. These assertions do not substitute for viewing the actual native pixels or establish all-frame motion/content comprehension.

Artifact contracts cover normal stems and the installed Playwright output-directory algorithm's truncated stems. These are filename-coverage cases, not claims of observed native output. Negative cases reject generic ledgers, request bodies, headers, storage, private suffixes, error context, wrong extensions, keys, databases, traces, video and identical names in unrelated fixture directories. The retained prefix is `inventory-keyboard-continu*` with exact filenames, not a blanket directory upload.

## Source-review correction

Independent v1 review found a fixture race: the gate was consumed before the awaited activation observation, but the rejection guard used a held-read counter incremented only after that await. A concurrent second GET could temporarily receive the old list. Exact final counts would still fail, so this was not a false-pass path. Version 2 sets a separate synchronous claim marker before any await, uses it to reject every non-gated later service read and to prevent re-arming, and retains all exact request/count/timing assertions. Source re-review and native execution remain separate acceptance steps.
