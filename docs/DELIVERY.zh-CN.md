# RouteWeaver 本地交付说明

这是一份可以运行的本地开发交付，包含控制平面、节点代理、托管 Xray 运行时和 Web 管理界面。它不是只有页面的演示稿，也不是已经完成生产验收的发行版。完整需求与逐项证据见 `docs/product/CAPABILITY-REGISTER.md` 和 `docs/verification/ACCEPTANCE-MATRIX-2026-10-19.md`。

## 先体验界面

Linux amd64 运行包解压后，在解压目录启动：

    ./routeweaver-control-plane --demo

打开 `http://127.0.0.1:8080`，使用启动输出中的演示账号。演示使用真实本地 API 和隔离数据；退出进程后删除演示状态。不要在此模式导入真实私人订阅或接入实际节点，也不要把演示端口暴露到公网。

普通用户从“获取订阅”和“调整分流”开始；管理员管理节点、线路、用户与服务策略。首次建立订阅时，先选择 ChatGPT 与其他流量的线路，再预览并发布。保存草稿不会自动修改已经发布的订阅。

本包面向 Linux amd64，不能直接在 macOS 执行。源码包提供构建入口；跨平台编译不等于已在对应设备验收。

## 这次交付的重点

- 多核心适配器架构：服务端意图、客户端配置、分流规则和目标渲染分离，不把 Xray 与 sing-box 写成封闭的双核心模型。
- 集中管理节点与线路，图形化链路配合表单入口；配置发布、回退与应用状态分开建模。
- 用户私有机场来源、节点处理、独立转换配置与订阅输出；策略组、规则文件、目标特性和原生覆盖都有明确能力边界。
- 平台自己的额度、倍率、周期与重置时间；在线 IP、并发流和限速与转换配置数量分开。供应商 IN+OUT 消耗独立于用户倍率用量。
- 托管 Xray 路径已经有真实本地数据流的用户限制与计量测试；不能把这些能力推定给所有 stock 核心或传输方式。
- 完整加密备份、维护用测试入口、架构规则、需求到任务的追踪，以及独立审查记录。

## 使用前仍需完成

1. 在支持的浏览器和主机上完成页面布局、键盘、移动端、下载与真实客户端导入验收。当前 DOM/API 测试不是截图或浏览器验收。
2. 在允许相应系统能力的主机验证 sing-box 进程运行。这里通过了原生配置检查，但进程启动受宿主机权限限制。
3. 接入实际 VPS 后核对 FRA → UK 与直连线路、实际证书、运营商统计口径和月度周期。这次没有修改你的 VPS，也没有使用真实节点凭据。
4. 私有仓库 `isning/RouteWeaver` 已创建。请核对当前提交对应的 GitHub Actions 结果；工作流文件存在、本地检查通过和远程 CI 通过是不同证据。本地任务清单不等于已经发布 GitHub Issues。

部分边界需要特别留意：私有规则文件目前通过配置与文件的 ZIP 包交付；混合不支持内容的来源采用整批拒绝而不是部分导入；供应商额度耗尽目前是提示，不会自动替换出口或停止节点。实际支持的协议、传输、客户端策略与版本请以能力表为准。

## 正式保存数据

持久化运行、加密主密钥、首次管理员初始化、HTTPS 反向代理和节点接入步骤见运行包的 `README.md`、`NODE-AGENT.md` 与 `MANAGED-XRAY.md`。密钥不要放进仓库或共享模板。管理操作通过 Web UI 进行；启动程序不等于已经为实际服务器完成安装与授权。

本轮源码恢复与验收范围见 `docs/verification/RELEASE-GATES.md`。历史检查结果不自动适用于当前修改。

源码验证入口是 `scripts/verify.sh`。`quick`、原生语法、原生进程、真实数据流和 `full` 是不同范围；具体执行结果保存在验证记录中，不把未运行或被阻止的阶段记为通过。
