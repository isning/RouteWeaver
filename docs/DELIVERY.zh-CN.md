# RouteWeaver 本地交付说明

这是一份可以运行的本地开发交付，包含控制平面、节点代理、Xray／sing-box 适配器、托管 Xray 运行时和 Web 管理界面。它不是只有页面的演示稿，也不是已经完成生产验收的发行版。完整需求与逐项证据见 `docs/product/CAPABILITY-REGISTER.md` 和 `docs/verification/ACCEPTANCE-MATRIX-2026-10-19.md`。

## 先体验界面

Linux amd64 运行包解压后，在解压目录启动：

    ./routeweaver-control-plane --demo

打开 `http://127.0.0.1:8080`，使用启动输出中的演示账号。演示使用真实本地 API 和隔离数据；退出进程后删除演示状态。不要在此模式导入真实私人订阅或接入实际节点，也不要把演示端口暴露到公网。

普通用户从“获取订阅”和“调整分流”开始；管理员管理节点、线路、用户与服务策略。首次建立订阅时，先选择 ChatGPT 与其他流量的线路，再预览并发布。保存草稿不会自动修改已经发布的订阅。

本包面向 Linux amd64，不能直接在 macOS 执行。源码包提供构建入口；跨平台编译不等于已在对应设备验收。

## 这次交付的重点

- 多核心适配器架构：服务端意图、客户端配置、分流规则和目标渲染分离，不把 Xray 与 sing-box 写成封闭的双核心模型。
- 集中管理节点与线路，图形化链路配合表单入口；配置发布、回退与应用状态分开建模。
- 用户私有机场来源、节点处理、独立转换配置与订阅输出；策略组、规则文件、目标特性和原生覆盖都有明确能力边界。
- 平台自己的额度、倍率、周期与重置时间；在线 IP、并发流和限速与转换配置数量分开。供应商 IN+OUT 消耗独立于用户倍率用量。
- 托管 Xray 路径已经有真实本地数据流的用户限制与计量测试；不能把这些能力推定给所有 stock 核心或传输方式。
- 完整加密备份、维护用测试入口、架构规则、需求到任务的追踪，以及独立审查记录。

## 使用前仍需完成

1. 在目标浏览器、主机与实际客户端上完成部署验收。仓库已有 Chromium 用户流程、窄屏和明暗模式检查，以及本地原生客户端订阅连接验证；这些是限定场景的证据，不代表所有页面、设备或真实网络已验收。DOM/API 测试本身仍不是截图或浏览器验收。
2. 在选定节点主机确认内核版本、系统权限、防火墙和证书。部分历史沙箱无法启动 sing-box，并不表示项目只有语法检查：CI 已包含原生进程及 Hysteria2/AnyTLS 真实回环流量门禁。运行结论必须绑定具体提交的成功 CI，不能外推到生产 VPS。
3. 接入实际 VPS 后核对 FRA → UK 与直连线路、实际证书、运营商统计口径和月度周期。这次没有修改你的 VPS，也没有使用真实节点凭据。
4. 源码通过 `isning/RouteWeaver` 交付。请核对当前提交对应的 GitHub Actions 结果；工作流文件存在、本地检查通过和远程 CI 通过是不同证据。本地任务清单不等于已经发布 GitHub Issues。

部分边界需要特别留意：私有规则文件目前通过配置与文件的 ZIP 包交付；混合不支持内容的来源采用整批拒绝而不是部分导入；供应商额度默认只提示；管理员可明确启用“暂停托管连接及续期”（`suspend-managed`），见下文。实际支持的协议、传输、客户端策略与版本请以具体能力声明为准。

## 供应商额度：提示与暂停不是同一策略

默认 `advisory` 不限制连接。该选项要求有限额度、明确的用量来源，界面仅在该服务器有托管 Xray 实例时提供。选择 `suspend-managed` 后，托管准入会在额度耗尽、供应商到期，或所选用量依据缺失、不完整、过期时拒绝新连接及续租；已有连接在短租约到期后关闭，而不是立刻停止整个节点进程。用量依据来自选定的网卡估算或手工账单，必须属于有效周期且足够新鲜；手工填写账单不等于自动向供应商核账。使用该策略时，需使配置、周期和用量依据重新满足准入条件。

该策略不自动切换出口，也不改用户额度/倍率；不能约束普通 stock 核心或外部已有凭据，不能保证供应商账单绝不超额。源码依据：`internal/observability/provider_admission.go`；原生连接关闭与拒绝测试：`internal/httpapi/provider_native_test.go`。

## 引擎差异与已验证范围

- Hysteria2：RouteWeaver 支持 sing-box 客户端 1.14.3 和普通 sing-box 服务端 1.14.3/1.14.4；目前仅直连，必须使用密码与 TLS。不支持 Hysteria2 链式中转，也不将其提供给 Xray、托管 Xray 或 Mihomo 输出。
- AnyTLS：同一 sing-box 版本范围，支持直连及限定的服务端命名连接器链：单个 SOCKS5、普通 TLS Trojan 或普通 TLS VLESS 中转，或两个普通 TLS Trojan 中转。不是任意组合，也不支持把 AnyTLS 作为其他协议的中转。客户端输出仍连接选定入口；中转私密凭据不作为公开入口订阅交付。
- 托管准入、用户计量与限制不能从上述普通 sing-box 支持推导得出。基于 principal 的计量监听仍限定 VLESS；普通核心与托管核心能力不等价。

准确字段、拒绝条件、导入范围和历史增量见 [`ENDPOINT-CAPABILITIES`](verification/ENDPOINT-CAPABILITIES-2026-10-29.md)。其中早期“仅直连/不支持”记录应结合后续命名增量阅读，而非当作当前完整清单。

验收基线 `dac191f0ae571bffe4cc4ee97cb7127683d82b4d` 的 [CI 43561751523](https://github.com/isning/RouteWeaver/actions/runs/43561751523) 已通过 21 个作业。已有本地完整链路验证涵盖建节点、编排托管 VLESS 入口与 Xray SOCKS 中转、分配用户、发布、下载订阅、官方 Mihomo 实际 TCP 连接及停中转后不绕过；这不是所有协议组合或真实 VPS 的生产验收。线上示例预览使用合成数据且不连接真实后端，不用于证明计量、部署、OIDC 或真实订阅可用。
