# RouteWeaver 正式能力与 User Story 清单

更新：2026-10-19。本轮联合核对已经确认完整能力范围：多核心线路平台、完整订阅转换与客户端配置管理、平台订阅中心、用户/服务运营、集群运维，以及复用和平台维护。不是缩减到原型或 MVP 的功能清单。

本清单包含 35 条已确认目标范围的 User Story，另保留 1 条当前范围明确暂缓的服务端自动切换记录。其中明确标注的 D01 在线 IP/入口限速、D02 重置默认值、D06 副本/引用策略已经确认；其余验收轮廓及尚未具体化的数值、数据结构、运行时执行方案仍为建议。用户已授权按完整 User Story 自主细化工程方案、拆分任务、完善 CI/测试并开始开发；重大产品取舍再核对，真实 VPS 部署、账号授权及长期凭据操作仍另行确认。旧 SPEC、UI 和交付切片需与本清单逐步对齐，不能反过来删减已确认需求。既有 IR、权限、秘密保护、身份和历史一致性约束继续保留。

## 如何读状态

- **已确认能力**：用户同意这一组能力属于产品范围，不代表其中每个交互、验收数字、客户端兼容组合都已批准。
- **候选，待核对**：尚未确认，不进入已确定范围。
- **明确不需要**：仅排除写明的能力，不扩大解释。
- “已确认策略/确认依据”以及 D01、D02、D06 中明确记录的业务定义是已获同意的决定；一般“验收轮廓”及未细化参数仍为**待审阅建议**。两者都不代表已实现或通过测试。编号只用于本文追踪，不是 GitHub Issue。

## D01 补充确认：在线 IP 数限制

用户（Sentinel_729f3d0110348191ae54b196134a9a4b）：“用在线 IP 数即可，这主要是机场的设备数限制需求 我们的多个订阅转换的配置另行建模”。在核对 FRA/LAX 等入口是分开计算还是账号全局计算后，用户（Sentinel_d356afedc6ac81919473641dcc58822c）：“是两边合并去重，和机场一样”。

据此确认：设备数限制采用**账号级在线客户端 IP 去重数**，不是物理设备身份。同一账号在多个平台公开入口使用同一客户端 IP，只计一次；计量取真实客户端入口 IP，不将中转 VPS 的 IP 当成客户端。用户自带外部机场的直连流量不纳入平台统计。多个转换配置、输出订阅和设备/IP 限制分别建模，不创建未要求的物理设备绑定或设备凭据槽位。

在线有效窗口与执行延迟仍需验证；后续八项方案已确认超限拒绝新增 IP、保留已获准 IP。此口径不意味着可以准确识别物理设备，也不预先承诺跨节点即时强制执行。

对于后续“速率也按账号全局吗”的问题，用户（Sentinel_8b1be687506c81918b5282b52aa57e46）回复：“emm,看机场怎么做的吧，我感觉技术上这样很麻烦啊”。当时全局汇总限速未确认；后续已选择入口独立限速，见 A04/D01 的最新确认。保留这段作为决策经过，不再作为待回答问题。相关 [核心限制能力检查](../research/core-limit-capabilities.md) 是源码检查资料，不是已验证运行时保证。

## D02 / D06 补充确认：重置与复用策略

**D02 已确认策略。** 助手提出：“支持每月固定日、按开通日滚动、固定天数周期和不自动重置，由管理员按服务方案设置。到期、续期、流量重置和订阅链接重置各自独立；默认续期不自动清零流量，未用完的额度不结转。”用户（Sentinel_8670645f61f08191b9a7246aa24e878b）：“我同意”。

按开通日滚动指以开通日为锚点的**日历月周年日期**，与每隔固定天数的周期分开建模。后续八项方案已确认默认 UTC+8、缺失月日取月末并在下月恢复原日、手动重置不改变下次自动重置日；迟到流量归属和实现边界继续细化。

**D06 已确认策略。** 助手提出：“同时支持‘独立副本’和‘共享引用’。复制模板后由用户独立修改；引用公共规则集或处理预设时，可以固定版本，也可以跟随更新。任何更新都不覆盖个人修改，兼容性检查失败则保留上一份有效配置。”用户（Sentinel_dbfb25bd9a548191adc9572af0688c0b）：“我同意”。

独立副本与共享引用是不同关系；共享规则/预设允许固定版本或跟随更新，保留个人修改，兼容失败保留上一份有效配置。具体覆盖优先级、冲突处理和版本合并规则仍待设计。这些策略约束控制面的候选生成与发布，不意味着所有客户端的运行时资源更新都天然提供相同原子性或回退保证。

**D04 当前范围。** 对是否必须支持任意 JavaScript 处理的问题，用户（Sentinel_4132252017f08191976cb4bb0e16cee1）回复：“没有，我用一”。“没有”明确表示目前没有必须依赖脚本的需求；末尾“我用一”不完整，不推断含义。当前暂不纳入任意脚本执行，保留扩展位置；完整结构化/可视化处理和可选原生高级覆盖继续纳入。这不是永久禁用，也不把原生配置编辑等同于执行任意脚本。

## 最终八项默认方案与推进授权：已确认

助手提出以下八项完整建议后，用户（Sentinel_937013b99c00819183687dc7057530d4）回复：“全部按推荐”。随后用户（Sentinel_f78a062bd480819185e02dccb7013f82）说：“我先休息了，我明天要早起”。这些确认不要求用户继续在线等待技术细化。

1. **首批兼容验收：**Xray／sing-box 服务端，Mihomo／sing-box 客户端；其他格式分批扩展，不删掉已确认能力。精确版本、协议覆盖和正向验证由工程研究落实。
2. **在线 IP 超限：**拒绝新增 IP，保留已获准 IP；同一客户端 IP 换平台入口不重复占名额。有效窗口、同步和执行延迟仍需实现验证。
3. **到期／停用／额度用尽：**停止账号访问，而不只是使订阅链接失效；已有连接如何终止及实际延迟由工程验证。
4. **短暂控制面断联：**不立即停掉全部线路；按最后有效权限和有界有效期运行，无法安全确认额度时限制访问。有效期数值及安全判断需要实现证据，不等于无限离线授权。
5. **日期规则：**默认 UTC+8；每月指定日不存在时取当月最后一天，下月恢复原日期；手动重置不改变下一次自动重置日，历史保留。开通日历月周年与固定天数仍是不同模式。
6. **备份与秘密：**管理员完整备份加密，包含恢复所需秘密；分享模板默认脱敏；正常订阅仍包含连接所需凭据。密钥管理、恢复验证和保留策略由安全工程细化，不授权将秘密传到任意第三方。
7. **账号与通知：**邀请制、本地账号，管理员支持二次验证；通知首批为站内、邮件、Webhook，其他渠道后续扩展。产品能力确认不代替真实账号授权、渠道凭据配置或具体外发权限。
8. **推进授权：**按完整 User Story 自主细化工程方案、拆分任务、完善 CI／测试并开始开发；重大产品取舍再问。真实 VPS 部署、账号授权和长期凭据操作仍另行确认，现在不需要提供密码。

此前产品核对期间的暂停与“所有实施细节需先逐项批准”不再作为开发阻塞。验收轮廓继续由工程细化并验证，而不是宣称已经实现/测试通过；本轮文档更新本身不执行生产操作。

## F. 已确认的基础边界

### F01 多核心控制面与节点执行

**状态：已确认能力。** 作为管理员，我希望通过控制面和节点 Agent 管理多个核心家族，以便统一管理而不被两种核心写死。

验收轮廓（建议）：VPS、核心实例和连接端点分开；同机可有多个实例；版本能力声明明确；支持/不支持/尚未验证分别表达。Xray、sing-box 是初始目标，不是永久枚举；不承诺任意核心完全等价。

### F02 图形化直连与中转

**状态：已确认能力。** 作为管理员，我希望创建直连或多跳中转线路，并通过图形或路径表编辑，以便清楚控制入口、经过顺序和出口。

验收轮廓（建议）：UK/LAX 单端点直连有效；中转按稳定端点身份验证真实循环，而不是简单要求物理入口/出口不同；改名不破坏引用；现有线路应用修改的用户影响可见，失败保留尝试过的草稿。

### F03 服务端和客户端意图分离

**状态：已确认能力。** 作为管理员及用户，我希望个人客户端编辑不会改变共享服务器线路或暴露内部凭据，以便各自安全管理自己的配置。

验收轮廓（建议）：服务端与客户端采用独立 IR；服务端渲染、运行时适配、客户端渲染独立；共用规则语义与资源引用，不共用越权行为。客户端导出不创建服务端部署，也不泄露内部中转凭据。

### F04 私有多用户来源及默认客户端使用

**状态：已确认能力。** 作为用户，我希望自己的机场和配置与其他用户隔离，并默认只在客户端使用，以便保留个人配置空间且不占用平台中转。

验收轮廓（建议）：来源、集合、配置和输出权限隔离；服务器处理私有订阅的运营者可见性在导入处说明；日志脱敏。使用外部上游进行服务端中转必须另有管理员明确授权。

### F05 额度与线路倍率

**状态：已确认能力。** 作为用户，我希望知道实际流量和倍率扣量；作为管理员，我希望按整条线路设定倍率，以便合理分配额度。

验收轮廓（建议）：实际 1 GB、2× 扣 2 GB；整条线路只扣一次，不逐跳重复；实际、加权额度、供应商 IN+OUT 分账；历史倍率不随当前修改回算。精度、跨版本切换和执行延迟仍需细化，不包含货币支付。

## C1. 多来源与集合

### C101 添加和维护多个订阅来源

**状态：已确认能力。** 作为用户，我希望导入并维护多个机场/订阅来源，以便集中使用不同供应商的连接选项。

验收轮廓（建议）：明确支持的订阅 URL、节点 URI、文本及配置文件输入方式，并保留来源归属；配置文件导入可提取节点，但必须说明保留/忽略了哪些配置内容，不能静默丢失后仍称完整导入。完整配置无损迁移是另一个兼容范围问题，不能由“支持导入”自动推出；添加、修改、刷新、暂停与删除可操作；坏输入/部分解析有具体诊断；失败保留上次成功接受的选项。首批目标为 Xray/sing-box 服务端及 Mihomo/sing-box 客户端，准确输入格式/版本由能力验证落实，不限制为原型单一输入。

### C102 建立可复用集合

**状态：已确认能力。** 作为用户，我希望把多个来源及选择结果组织成命名集合，以便不同配置和输出复用同一整理结果。

验收轮廓（建议）：集合可引用多个来源并更新成员；能查看结果及来源；重命名保留引用；删除展示依赖；更新不悄悄替换含糊身份的成员。集合嵌套等具体规则另行细化，不由这里自行批准。

## C2. 节点处理与中间预览

### C201 筛选、重命名和排序

**状态：已确认能力。** 作为用户，我希望按条件筛选、批量命名并排序节点，以便得到自己能理解且有用的节点列表。

验收轮廓（建议）：每个来源可独立配置处理步骤，来源结果按明确顺序合并后还能配置集合级处理；完整链路为“来源处理 → 有序合并 → 聚合处理”。各阶段步骤有明确顺序，可启用/停用、修改及预览；名称变化不改变连接身份；筛选条件及排序稳定性可解释；错误步骤定位到具体输入/条件。

### C202 去重与字段覆盖

**状态：已确认能力。** 作为用户，我希望识别重复连接并覆盖必要字段，以便合并来源时避免冗余并适配客户端。

验收轮廓（建议）：同名不直接等于同连接；去重保留来源信息且规则可见；去重和字段覆盖可作用于单来源或合并后聚合结果，适用范围、跨阶段优先级和目标兼容检查明确；不接受通过覆盖跨用户取密或修改管理员拓扑。

### C203 检查各处理阶段

**状态：已确认能力。** 作为用户，我希望逐步查看处理前后的中间结果，以便知道哪个步骤删除、重命名或改变了节点。

验收轮廓（建议）：原始标准化结果、各来源处理结果、有序合并结果、每个聚合处理步骤及最终结果可对比；显示增删改和原因；不保存也能预览；敏感字段默认遮蔽；无变化不创建虚假的待发布修改。

## C3. 嵌套、动态和策略组

### C301 自由嵌套与动态成员

**状态：已确认能力。** 作为用户，我希望策略组能引用其他组及按条件动态选取成员，而不是被固定的两层分组限制，以便构建复杂分流结构。

验收轮廓（建议）：支持任意有效层级的意图建模；检查自引用/循环和无成员情形；动态条件结果可预览，来源更新后的成员变化可追踪。任意嵌套不等于无限资源或所有目标无限层级，目标限制必须具体报告。

### C302 明确策略语义

**状态：已确认能力。** 作为用户，我希望配置手动选择、URL 测试、故障切换和负载均衡组，以便按用途选择连接方式。

验收轮廓（建议）：manual、url-test、fallback、load-balance 的意图、成员与参数可编辑；在目标支持相应语义时正确输出；不支持时明确指出，不能把不同策略静默当成手选。显式 fallback 是用户配置的策略，不是系统擅自换出口。

## C4. 完整有序规则与文件资源

### C401 管理匹配、顺序及动作

**状态：已确认能力。** 作为用户，我希望完整表达客户端分流规则的匹配条件、顺序与动作，以便控制流量去向而不是只选少量预设应用。

验收轮廓（建议）：有序规则、组合匹配、目标组/动作及最终默认行为可编辑并预览；不以原型 ChatGPT 示例限定产品；目标能力矩阵列明匹配语义，不能承诺任意客户端全特性等价。

### C402 引用和维护规则文件

**状态：已确认能力。** 作为用户，我希望规则优先使用可更新的文件资源，以便复用完整规则库而不把订阅撑成大量内联内容。

验收轮廓（建议）：资源来源、格式、版本、更新/固定策略可管理；缓存/私有交付/完整性错误有具体处理；按目标使用兼容文件，SRS 不通用；不支持语义不能静默省略或展开。资源细节留在编辑/诊断，不塞到日常首页。

## C5. 完整客户端配置管理

## X. 明确不需要与不应误删的边界

- **X01 明确不需要：外部机场的用量、到期、重置时间聚合。** 不需要把用户自带机场做成另一套账单/额度看板。
- **仍然需要：**这些机场的导入、更新、节点整理、集合、策略组、规则、完整配置转换与输出。X01 不能被扩大为“不支持外部机场管理或处理”。
- **X04 当前暂缓：**任意脚本执行；用户确认没有必须依赖脚本的需求。完整可视化处理与原生高级覆盖不削减，未来需求可重新评估。
- **X03 已确认当前暂缓：**服务端自动故障切换；保留扩展位置，不削减客户端显式自动策略。
- **X02 当前排除：**商业支付、订单、优惠券、货币账单/收款。线路倍率是流量额度扣量，不是支付产品。
- **不是承诺：**所有核心/客户端功能完全等价、任意嵌套无限资源、任何转换均无损、所有设备限制已有执行能力。这些由逐目标能力与验收证据决定，不能借此把完整转换器需求缩水成原型功能。
