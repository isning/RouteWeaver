| ID | 已观察问题与边界 | 本轮决定 |
|---|---|---|
| CT-01 · P1 | 集合来源字段只有已有来源选择，缺少任务内添加入口。保存或明确放弃后去来源页、再重开仍可完成；不是死路。既有空编辑器截图只有零选中，零库存分支由源码确认。 | 在来源字段提供“添加来源”，返回同一未保存集合；明确独立来源保存与集合草稿引用。 |
| CT-02 · P2 | 收起的来源行只有名称／顺序，来源专属处理的用途及已有步骤须展开才知；可点击到达不等于容易发现。 | 收起时显示“来源处理”，非零时显示已配置步骤数；保留来源身份、排序和完整展开编辑。 |

发现来自既有截图与源码的启发式审查；优先级是项目判断，不是用户实验结果或 WCAG 等级。集合仍是可复用处理配方：逐来源处理不修改共享来源，合并后处理是独立阶段；不因只有一个来源而取消它，也不把集合保存说成发布。

### CT-01 一条连续任务，多个明确保存边界

“添加来源”是当前集合的子任务；同一时刻只有一个可见编辑任务。进入、失败、取消或返回时，集合名称、已选来源顺序、逐来源步骤及合并后步骤必须保持。添加成功返回来源触发入口；确认真实焦点在动画结束后仍合理，不只验证瞬间 focus 调用。

| 转换 | 改变的对象 | 不改变／不能推断的内容 |
|---|---|---|
| 开始添加、取消未保存来源 | 当前子任务界面；按真实 dirty 状态决定是否确认 | 不保存或重建集合，不丢父草稿 |
| HTTP 保存失败 | 保留来源子任务的输入、错误与重试能力；父集合草稿继续保留 | 不把失败当成来源已保存，也不自动关闭子任务返回集合 |
| 保存符合使用条件的来源并返回 | 来源独立持久化；仅把其稳定引用追加到当前集合草稿 | 不自动保存集合或 Profile，不发布或更新任何订阅 |
| 之后取消集合 | 按明确决定丢弃集合草稿 | 不撤销已成功保存的来源；不暗示整体事务回滚 |
| 保存成功响应仍有候选／诊断待处理 | 返回集合提示，保留已保存来源及真实诊断；来源不自动选入集合 | 不静默接受候选，不标成已就绪 |
| 前往来源页处理诊断 | 经真实离开守卫；明确放弃后继续目标导航 | 取消导航保留集合草稿；该分支不是完整就地恢复 |

子任务的未改、已改、提交中、失败必须按真实状态处理，不能以统一“正在编辑”代替 dirty/pending 守卫。重复操作、后台响应和父列表刷新不得扩大写入范围。

**已知身份与权威新鲜度分开。** 成功保存后已知的来源 ID 和名称应立即支持返回的草稿；来源列表重新读取延迟或失败，不应让名称退化成无意义 ID。保留可信展示信息不等于宣称列表已刷新，也不能隐藏真实读取失败或合成可用状态。

### CT-02 收起也能识别阶段与配置

“来源处理”说明该行的展开用途，非零数量表示**已配置步骤数，包含停用步骤**，不是“正在执行”或“已生效”的数量。零步骤不增加一段教学文案。来源名称与顺序保留，逐来源处理与合并后处理的归属不变；展开／收起只是展示变化，排序必须连同该来源的步骤一起移动。

拒绝的替代方案：要求先保存集合再离开、自动保存父草稿、自动接受来源候选、展开所有来源代替清晰摘要、用更多说明掩盖无入口。它们分别增加不必要决定、混淆写入范围或未解决可发现性。

## 已覆盖的复测合同

- **连续性与范围：** 零／一／多来源；预先命名、重排及两层非空步骤后开始添加；成功或取消返回原草稿；HTTP 保存失败保留子任务输入与父草稿，支持继续重试或取消。独立保存来源存在，集合／Profile／发布无隐藏写入。
- **未就绪与恢复：** 保存但待处理时不选入来源；诊断真实可见；前往已有来源页须经过离开守卫，取消保留草稿，明确放弃后才能继续。不能把这个例外写成所有恢复均在原任务内完成。
- **读取与控制：** 新来源名称在列表未返回和读取失败时仍可识别，同时读取状态诚实；pending 防重复，dirty 离开确认，迟到结果不重开旧任务或写入新草稿。
- **处理与可发现性：** 收起显示用途和非零配置数，含停用步骤；展开、排序、保存后重开保持步骤归属及两层顺序。预览与显式保存仍可用。
- **实际界面：** 桌面、390／320 px；正常与异常状态分别检图。错误正文、恢复按钮、来源身份和排序可读可达；检查键盘返回及动画结束后的自然焦点，不以脚本主动纠正焦点取得通过。
