# 列表控件一致性

## 本轮范围

依据用户要求，从各列表的实际查找任务审查控件设计、搜索、筛选和恢复行为。不是给每个页面重复添加不同的工具栏，也不要求不同领域具有相同筛选维度。

发现：来源、规则资源、消息的快速状态筛选分别实现，未选中样式与间距不一致；规则资源的筛选另起一行，即使宽屏也不能与搜索对齐。线路与规则资源筛选空态的清除动作会移除当前按钮，却未指定回到搜索框。集合预览只有翻页与阶段切换，难以跨阶段追踪某个连接。

## 共享规则与实现

- 搜索使用现有 SearchField：图标、44px 触控高度、键盘清除与回焦一致；增加搜索键盘动作提示，保留现有输入可访问角色，避免无意义的语义变更。
- 快速互斥状态使用新增 QuickFilters：selected=secondary、unselected=ghost、gap-2、aria-pressed、可选数字计数。来源、规则资源、消息共用，不再分别拼装。
- 搜索与筛选属于同一 ResourceToolbar。空间不足自然换行，不固定拆成两块；领域选择数量多时继续使用带标签的 ChoiceSelect，而非强塞按钮。
- 行动与真实业务状态保持原样；不会为统一而隐藏暂停、失败、未知或危险后果。
- 规则资源与线路清除空态筛选后回到搜索框；来源搜索忽略两侧空白，与其他列表一致。
- 集合预览沿用同一搜索控件，按名称/地址/地区/协议过滤。同一个查询贯穿阶段切换，用户能在最终结果无匹配时查回原始输入。筛选变化回第一页，既有阶段统计不被改写为筛选后总量。

## 验收边界

相关组件及页面任务使用现有 DOM 公共交互边界验证；本地 Chrome 受宿主 socket 限制未完成视觉验证，不能用源码类名证明对齐结果。CI 与实际截图仍应逐项检查。全站其余表格、下拉筛选和行操作的逐页覆盖仍未完成。
