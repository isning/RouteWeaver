# 列表控件一致性

## 本轮范围

依据用户要求，从各列表的实际查找任务审查控件设计、搜索、筛选和恢复行为。不是给每个页面重复添加不同的工具栏，也不要求不同领域具有相同筛选维度。

发现：来源、规则资源、消息的快速状态筛选分别实现，未选中样式与间距不一致；规则资源的筛选另起一行，即使宽屏也不能与搜索对齐。线路与规则资源筛选空态的清除动作会移除当前按钮，却未指定回到搜索框。集合预览只有翻页与阶段切换，难以跨阶段追踪某个连接。

## 共享规则与实现

- 搜索使用现有 SearchField：图标、44px 触控高度、键盘清除与回焦一致；增加搜索键盘动作提示，保留现有输入可访问角色，避免无意义的语义变更。
- 快速互斥状态使用新增 QuickFilters：selected=secondary、unselected=ghost、gap-2、aria-pressed、可选数字计数。来源、规则资源、消息共用，不再分别拼装。
- 搜索与筛选属于同一 ResourceToolbar。空间不足自然换行，不固定拆成两块；领域选择数量多时继续使用带标签的 ChoiceSelect，而非强塞按钮。
- 行动与真实业务状态保持原样；不会为统一而隐藏暂停、失败、未知或危险后果。
- 规则资源与线路清除空态筛选后回到搜索框；来源搜索忽略两侧空白，与其他列表一致。
- 集合预览沿用同一搜索控件，按名称/地址/地区/协议过滤。同一个查询贯穿阶段切换，用户能在最终结果无匹配时查回原始输入。筛选变化回第一页，既有阶段统计不被改写为筛选后总量。

## 验收边界

相关组件及页面任务使用现有 DOM 公共交互边界验证；本地 Chrome 受宿主 socket 限制未完成视觉验证，不能用源码类名证明对齐结果。CI 与实际截图仍应逐项检查。全站其余表格、下拉筛选和行操作的逐页覆盖仍未完成。

## 管理列表的实际应用

公告和发送记录此前只有翻页，无查找能力。本轮再应用同一 ResourceToolbar/SearchField/QuickFilters：公告按标题或正文搜索，按受众筛选；发送记录按标题搜索，按渠道筛选。两者保留真实状态与已有错误恢复，公告以“匹配数 + 总数”、发送历史以“匹配数 + 已加载数”表达当前集合；过滤变化回第一页，无匹配可以清除并回焦。公告编辑后如原行退出结果集，也回到搜索框。未知渠道在全部中仍可见，不被误归为已知渠道。没有增加自动发送、批量已读或重新投递。

有界验证：公告/发送历史的 16 项 DOM 任务通过，类型与构建通过。不同来源/规则资源/消息筛选保持各自有意义的选择，不为了形式统一而塞入无用条件。

核查后端发现消息上限 200 条、发送历史上限 500 条；因此两者明确搜索已加载记录，计数使用已加载而非全量，不把“无匹配”当作整个历史不存在。

## 转发路径列表

同一规则继续用于转发路径：按名称查找忽略首尾空白；配置草稿使用“全部 / 已保存 / 需要调整”快速筛选，与搜索取交集。状态严格沿用现有 diagnostics 判定，不等同实际部署或健康。筛选变化回第一页，异步数量缩减时收敛页码。无匹配提供清除筛选并回焦；详情关闭且原行已退出结果集时回到搜索框，不改变保存后进入详情的流程。

## 第二组合并：基础设施与管理清单

- 服务器、核心实例、监听端点共用搜索框布局，但各自保存查询；只匹配当前清单展示的名称、地址、服务器、版本或协议，不读取凭据或调用 reveal。工作区返回优先恢复原行，原行退出结果才回到搜索框。
- 用户组按组名/方案名查找，服务方案保留下拉选择和缺失引用，不把成员名单纳入搜索。任务历史按已有任务/路径身份查找，状态来自实际记录，未知状态仍可见。
- 用户、服务方案、旧端点、旧链路以及计划实例选择器统一忽略首尾空格；查询变化回首页，刷新使结果缩小时收敛页码。计划实例的勾选与执行顺序不随过滤清空。
- 本轮属于同一搜索、分页、空态与焦点规则的应用，不给所有领域强塞相同筛选条件。审计历史查找和进一步视觉细化仍留待下一轮。

## 操作审计与诊断历史

操作审计沿用共享搜索/筛选工具栏，支持现有可见的操作标签、代码、对象、账号与审计标识；动态操作类型保留未知代码与当前筛选。查询变化回首页，无匹配可清除回到搜索框。后端返回完整审计列表，计数表达总量而非采样量；没有新增请求、记录写入或权限变化。

节点诊断历史按目标、测试类型和路径模式搜索，状态使用真实记录生成的选项并保留未知值。筛选发生在已接收任务回执与列表合并之后，详情仍从未过滤集合查找；创建、轮询、取消与任务接收逻辑不变，避免筛选使详情失去当前任务。

## 跨列表查找收尾

进一步检查真实查找任务发现并补齐三处：来源搜索与状态筛选现在回首页，避免仍有多页时停在原页；线路完整地址的显示和搜索共用同一格式，复制对外地址后可直接查找；订阅零结果的清除动作恢复搜索焦点。保留既有 IPv6 展示、来源状态判断和订阅上下文恢复，不新增请求或写入。
