# 三栏比例修订

基线 9f0c000，用户明确否定 v10 的三栏宽度和视觉效果。CI14 通过不代表该布局已被接受。

## 实际观察

重新查看用户 Cloudflare 参考 04/05/09 与 CI14 settings/profile/subscriptions 1280、展开用量 1440。此前统一 14rem：目录占用过多空白，用量卡扣除双重间距后正文仅约 167px；1280 主区约 704px，Profile 的外层断点又强制连接/流量纵叠。上述是已见像素问题，不以无溢出代替视觉判断。

## 新宽度预算（项目适配，不是从未知 DPR 截图反推 CSS）

- 全局桌面导航 14rem；桌面内容与面包屑 gutter 1.5rem，手机保持 1rem。中文菜单、折叠语义与点击高度不变。
- 目录仅 11rem，间隔 1.5rem；自身可用内容宽度到 61rem 后才侧置，主区至少 48.5rem。桌面当前位置用细侧标记，取消宽灰色选中块；44px 点击高度/焦点保留。
- 用量数据栏 18rem，间隔 1.5rem；内容宽度到 68rem 后才侧置，主区至少 48.5rem。去掉卡片外重复的栏边框与内边距。1280 通常顺序放在主任务后，1366 是否侧置仍看实际容器而不是硬判视口。
- 历史决策：保留原 96rem 外框上限并起始对齐。此决策已被下方「超宽窗口纠正」撤回；它在更大有效布局宽度下把右栏留在中间，不能沿用此前 1920 检查作为认可。
- ContextHeader 与 ContextLayout 共享列预算：新建分流配置、Profile 保存/检查对齐主任务右边，不漂到目录或用量栏之上。Profile 的 sticky 行自身仍处在整页流中，不被短 header cell 限制粘滞范围。
- Profile 连接/流量基于该卡自身内容宽度 44rem 分栏，分隔线使用完全相同断点，不根据含目录的祖先宽度猜测。
- 辅助用量在主区下方时，已有线路与用量可并列；不复制数据子树或发起新查询。

## 新验收合同

沿用真实交互与 GET fixture，不删旧的草稿/焦点/滚动/零写入断言。新增：

- 1280：目录主区至少 800px；订阅数据栏回到下方时主区至少 1000px。是对旧约 704px 的明确改善目标，不仅“不溢出”。
- 侧置目录 176px / 数据栏 288px，间隔 24px；开栏时主区至少 776px。边界两侧分别用 1240/1260、1352/1376 实际容器测量。
- 订阅新建与 Profile 检查动作右边对齐主区；标题左边也对齐主区。运行设置定位后验证保存栏仍处于 sticky 顶端。
- 展开后的数据卡正文至少 250px；同一服务与线路长名称仍直接可读。截图检查其行宽/密度，不以 scrollWidth 一项作最终设计结论。
- 使用两个有名称的内置连接，展开来源控制；1024 及以上验证连接/流量实际同排且每列至少 340px，窄屏仍顺序排列。
- 1536/1920 骨架→数据保留同一 main 横坐标和宽度。整页起始边在侧导航后约 24px，不产生居中大空沟。输入长度与长说明单独受限。

旧 CI14 图是本次设计目标不满足的基线，不冒称已在旧代码运行新断言。当前环境不启动浏览器；这些几何断言与新像素由下一轮 CI 执行，作者及独立审查据实际新图决定是否接受。

## 超宽窗口纠正（基线 16d5aaf）

用户提供的 v11 实际截图显示：用量栏停在工作区中部，右侧留下大片空白。截图存储尺寸不是 CSS viewport，不能据此认定浏览器缩放或 DPR。已核对预览专用样式：仅预览提示条及侧栏高度 inset，没有全局 zoom、scale 或字号覆盖；不修改预览安全边界来掩盖这个问题。

确定的源码限制是 main 上的 96rem max-width。主页面容器继续占满窗口，但包含 primary 与 rail 的 main 被截窄。因此删除 main 的整体上限，让外框使用 sidebar 后的全部可用宽度。保留 24px 桌面 gutter、16px 手机 gutter、两种 rail 宽度/启用预算、主操作对齐，以及字段和说明各自的阅读限宽。骨架和成功内容仍共用同一个外框。

新增实际浏览器验收：

- 除原有 320–1920 外，加入 2304/2560/2880/3440；图像使用测试实际 CSS viewport，不从用户截图推测。
- main 右边等于 documentElement.clientWidth；内容框右边只留约定 gutter。
- 侧置 rail 的右边等于内容框右边，距离窗口右边为 24±1px；不允许 rail 外剩余空间随视口增长。
- 仍验证目录/数据独立宽度、主区最低预算、header 操作锚点、窄屏重排、内部输入限宽、URL 换行、焦点/草稿/零写入。
- 2560/3440 的加载与完成外框宽度相同，避免加载后收缩。

当前环境不启动浏览器。新断言将由下一轮 CI 执行；源码、DOM 或类型检查不能代替新的超宽截图及实际效果判断。
