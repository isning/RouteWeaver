# RouteWeaver 产品设计原型 v0.2

本次是任务结构与默认信息层级的重做，不是功能实现。直接打开 `index.html`；无需网络或依赖。默认进入个人「我的订阅」，顶部评审工具可切换管理空间，以及日常使用、更新失败、首次使用。也支持 `?view=personal|admin|usage|sources`。

## 本轮取舍

- **先使用，再编辑。** 个人首页只展示当前订阅、分流摘要、额度和「获取订阅」。点击「调整分流」才进入线路选择，规则文件与 DNS 再按需展开。
- **先运营，再建模。** 管理员从线路列表进入详情；默认看入口、出口、倍率与授权范围。只有编辑时显示有序表单与图形路径；逐实例版本、ID 和规则资源在技术详情中。
- **当前与草稿分开。** 保留当前已发布配置，草稿有单独入口。失败场景是具体的发布前检查或规则下载失败，不把现有配置一同变成不可用。
- **减少重复。** 删除原型界面内重复的免责声明、能力防御句、计数和工程解释。倍率放在线路选择与用量明细中，计算方法按需打开。原型说明集中在外部评审工具栏与本文。
- **每步有清晰目的。** 获取订阅先选客户端，再给导入步骤；创建线路先选路径、倍率与谁可使用，再预览部署，发布在部署之后单独确认。

## 可以体验什么

1. 个人：打开获取订阅，选择客户端；调整默认线路和 ChatGPT 规则，保存本页草稿，预览修改、返回编辑或放弃。来源是可选项，不阻止直接使用平台线路。
2. 管理员：列表进入线路，查看摘要或技术详情；编辑路径、添加／移除中转、修改倍率与使用范围；重复实例产生原位错误；保存本页草稿或进入部署预览。
3. 首次使用：个人创建第一份订阅草稿，管理员创建第一条线路草稿，展示首次发布前的逻辑顺序。
4. 更新失败：用户看到具体的规则文件下载失败，管理员看到 UK-01 部署前连接检查超时。当前已发布配置仍然单独保留。
5. 键盘：原生按钮、单选、下拉、折叠详情与对话框；图形路径由同一组有序表单值驱动，操作不依赖拖动。窄屏使用单列与有标签的表格行。

## 原型边界

所有名称、连接、数据与状态均为固定演示数据。本页状态仅存在于内存，刷新即恢复；未修改 `web/`、后端或任何真实账号。

无外部资产、请求、API、存储、认证、真实来源导入、订阅凭据或剪贴板写入。真实发布、部署、重试检查、导入、复制订阅链接停在最后一步，不执行，也不显示成功结果。它们不是为了凑功能数量的无效导航，而是明确的外部执行边界。

本稿没有证明任意真实核心／客户端兼容、真实计量、跨倍率精度、执行阈值或可用性。这些是实现与测试的责任，不作为日常界面的防御文案。服务端处理私人来源的必要隐私披露仍紧邻地址输入。

## 待审阅

- 现有配置和待发布修改是否容易区分？取消编辑／放弃草稿会否误解成删除已发布配置？

- 图形与顺序表单是否一致；添加中转是否自然；重复实例错误是否就近且保留输入？
- 1440、1024、768、390、320 像素以及键盘操作是否无溢出、遮挡或焦点丢失？
