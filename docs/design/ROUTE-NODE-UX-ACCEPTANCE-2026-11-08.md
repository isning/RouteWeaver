### Implemented scope

- **Concurrent public-line edit recovery.** An existing-line save conflict can read the latest version of that exact line and offer explicit choices for the name, ordered path and endpoint selection, and public address and port. Continuing changes only the local draft and reviewed revision. A fresh check and a separate save are still required. Cancellation retains the original inputs, including raw port text. Missing identity, an unusable or unchanged revision, and a new-line ID collision do not silently become an overwrite. The initial increment is `96432c3`; subsequent lifecycle corrections in `080e4a4` preserve a completed preview during same-target navigation while rejecting late results from an abandoned view.
- **Server workspace and setup continuation.** A durable server view separates overview, cores and listeners, configuration records, and diagnostics. Registration, recorded Agent reports, and observed connection state remain distinct. Listener creation and path continuation retain the selected server and core, with an explicit return to that context. The workspace increment is `b83a577`. The latest owner-guard correction in `dab7d9a` checks authoritative inventory at action boundaries, including editors opened from the overview, while retaining drafts and already issued credentials when the original owner changes. Loading or failed refreshes are not treated as confirmed removal.
- **TLS correction within the current public-line task.** The repair entry is limited to the exact supported TLS rejection for the current draft and target. The parent sheet exits before the repair surface mounts. Listener edits retain their own impact, revision and save checks; adopting an updated listener into a path and saving server-private TLS settings remain explicit steps. Returning uses a fresh summary and an explicit recheck, without automatically saving the public line or applying a route. The module also preserves raw numeric input across remounts. The initial increment is `d86b32a`; `56989d2` separates the initial listener comparison from the editor, and `a4ea6ec` restores the parent inspection focus before starting the authorized recheck.
- **Gradual structured policy editing.** `1d373fa` adds default direct, reject and valid existing-connector choices for supported stock Xray and sing-box targets. `91e9963` adds independent action controls for existing supported domain, domain-suffix and IP-CIDR rules. Rule conditions, order and stable IDs are preserved. Connectors, user principals and rule resources have distinct readable sections. Unsupported rules remain individually read-only where safe, rather than disabling unrelated supported rules. Unknown fields are retained; managed or incompatible targets, ambiguous IDs, missing or cyclic connectors, legacy egress and conflicting exits remain guarded.

These are bounded task improvements, not a complete structured policy authoring system. Creating or reordering conditions, editing connector parameters or dependencies, and unsupported rule or resource forms still use complete JSON where permitted. The complex-policy guard remains in place so ordered route editing cannot discard policies. Saving inventory does not connect a machine; saving intent does not apply it.

### Implemented forms and source workflows

- **Conditions and rule lists.** Supported stock targets have domain, domain-suffix and IP-CIDR condition forms, default and per-rule actions, rule creation, ordering and confirmed deletion. Sing-box additionally supports nested AND, OR and NOT groups and references to existing eligible rule resources. Xray is restricted to leaf conditions supported by its compiler. Known children can be edited independently while unknown subtrees remain intact; destructive whole-subtree operations are blocked when preservation cannot be established. Nesting follows the supported root-at-zero depth limit of 128. Rule-list work is recorded at `685ef5475b875dba6e1416012cca579d64a05f5b`, with recursive conditions at `6818ba5e9ca2bfc906ce79b28dc66d8bae2ee683`.
- **Connector editing and collections.** Address and upstream selection are joined by the shared outbound connection form for supported protocol, port, authentication, transport and TLS settings. New connectors use an isolated temporary form and require an existing explicit valid default action; adding one does not silently change traffic destinations. Deletion requires confirmation and is blocked by default, rule, principal or upstream references, including unknown reference semantics that cannot be proved safe. Connector IDs remain stable and cannot be renamed. Unknown fields are preserved; removal of unknown TLS or transport structure is blocked, and malformed form objects remain read-only. Full connection forms are recorded at `cd5e954547651be671d9dfca38cdcd27c91cbaa8`, with connector collections at `16d681634398a665c4068c62e73a3a3496f6e7a4`.
- **Principal source workflow.** A principal row can verify its account, subject, route and credential version against the authorized source and use route resolution to verify the deployment and listener. A second explicit action opens the account-wide existing entry-management workflow. It does not edit principal IR directly or automatically reveal credentials. The original policy draft remains available, but entering management synchronously blocks saving that captured draft. Explicit discard and a fresh read are required before saving can resume; merely cancelling the source task does not undo source changes or make the old draft safe. The source integration began at `dd68b28802cad2e98f9af45583a830ded9f9aa65`, followed by the authoritative source-resolution correction at `a8fe84df9e5e3c8a2f9658892c02ecde73416ce0`.

Adopting form changes modifies the local policy draft. Saving the draft, checking it and applying it remain distinct actions. CAS, authorization and server-side validation remain authoritative.

### Deliberate support boundaries

Resource references are editable only by choosing existing eligible descriptors. Creating or editing descriptor URLs, digests, revisions and update policies is not part of these forms. Unknown engine versions, schemas and unsupported condition nodes remain read-only at the relevant scope and retain their original data. Managed and principal-linked policy protections have not been relaxed. These limits do not imply that supported condition authoring, rule ordering or connector editing is still missing.
