## 已确认发现与有界复测

### RF-01 错误以具体位置为单位

同一缺失连接可出现在组及两条规则，修复入口必须指向各自位置，而非第一个同名引用。项目实现按控件位置去重；不能把同一引用的不同错误合并掉。源码依据：`web/src/profile-validation.tsx` 的 occurrence 绑定／控件级去重，及 `profile-validation.dom.test.tsx` 的重排、删除和 same-reference 场景。

真实后端浏览器验收证明第二条规则和组各自聚焦正确位置，保留目标、输入及未选订阅；重新检查和明确确认之前不发布。初始390宽度被长 ID 撑至612–614，焦点正确但控件不可完整见；窄修 flex 后同时检查320／390页面宽度和完整可见性。

证据：EV-01 及[缺失去向修复验收](MISSING-ACTION-REPAIR-BROWSER-ACCEPTANCE-2026-10-22.md)。同一冻结源分别新任务3/3和原任务19/19，**不是一轮22/22**；后续迁移仅发现22项，不能推断组合执行通过。关联 UX-01/10/11/12；GS-01/07/08。

### RF-02 原生 label 比 locator 命中更接近真实操作

共存的 Resources 表单共享未命名空间的字段 ID，可见导入 label 指向隐藏编辑字段。原生 `label.control`、点击后焦点和键盘输入三个断言均 RED；Form namespacing 候选后 DOM 三文件26项通过，类型检查通过。

证据：EV-02、EV-07。真实浏览器补证：可见导入 label 指向活动输入，点击聚焦且键入成功。未选择／提交文件，不扩称全产品标签审计或辅助技术验收。关联 UX-10/11；GS-01/08。

### RF-03 账户与会话不能共享一个生命周期键

认证候选区分账户／角色拥有的私有缓存与草稿、会话代次拥有的 CSRF 和短期响应。普通核对保留但冻结工作区，真正失效隐藏主体及门户；已发请求可能已经提交，不重放写入。文件读取准备必须保留发起身份并在实际 POST 前核对。

证据：EV-03。15:44五个真实浏览器任务5/5、前后源一致：同A续接、B隔离、chooser与原生focus、真实已提交保存、离线恢复。均为本地合成demo，非真实账号或线上授权证明。这轮早于最终完成归属修复，不能签收16:18集成源。

**未关闭**：更早一次真实浏览器运行有一次真实退出后未在正常断言期限见登录标题，下一轮未复现，原因未明。不得称“退出问题已修复”。关联 UX-01/07/09/11；GS-09–11；具体身份合同为项目决定。

### RF-04 晚登录 body 不拥有当前身份

旧登录／邀请成功 body 在另一标签页已改变 cookie 后才到达，会把已接纳的B重新写成A并清B草稿；旧表单失败还可能清除后续 token。候选改为通过 `/auth/me` 核对实际身份，表单结果和 token 修订分别受归属保护；未把此问题称为后端租户越权。

证据：EV-04。六个新增公共接缝回归在原基线 RED，修复后28项认证测试 GREEN，关联10文件133项及类型检查通过。该修复已纳入16:18集成源；最终组合浏览器另见EV-14；RF-03的历史5/5不认证这个后续修改。

### RF-05 旧保存成功与当前完成回调分开

服务端已成功不能被假称撤销，但旧视图／草稿的回调也不能关闭或改变当前任务。回调须在发起 mutation 时捕获，不能由重渲染后的最新 options 偷换归属；同 hash 的有效完成也只消费原授权一次。

证据：EV-05。基线两个真实页面 DOM 用例证明：保存等待期间原生Back接受列表位置后，晚 Public／Server 保存会重开旧详情；另两个回调捕获消融用例证明，只保留 lease guard、改用最新 onSaved 仍会影响后续任务。修复后7文件99项和类型检查通过，每次服务端成功仍刷新相关清单缓存，即使视图已经离开。已纳入16:18集成源；不是浏览器最终验收。关联 UX-01/07；具体归属规则是项目方法。

### RF-06 hidden 属性不等于像素不可见

认证浏览器执行者看到自定义中文文件按钮下仍有重复英文原生文件控件；`hidden` 可能被组件 CSS display 覆盖。这是实际视觉问题，不是靠缩短文案就能解决的重复说明。

证据：EV-06、EV-14。旧5/5源不含后续CSS修复；最终33项中的文件选择任务验证原生输入隐藏、自定义chooser工作、同名文件变化内容再次读取、会话续接后保留第二份内容及文件名。最终业务截图像素复核显示中文按钮与文件名，无重复英文原生控件；此图只证明可见文件区域，不扩称整个长对话框可达性验收。关联 UX-04/10/12；GS-08/13辅助，发现本身来自本轮像素审查。

### RF-07 移动确认需同时量尺寸与对齐

最初320／390确认按钮均88×38，低于项目既有44 px目标。共享移动selector修复后3/3通过，但320按钮宽度244／236暴露相邻按钮 margin 的 specificity 问题；高度过线不等于布局一致。

证据：EV-07，15:54:25–15:54:36，3/3、前后源清单一致；390两按钮151×44，320两按钮244×44且left均38，computed margin均0，保稿和安全默认焦点通过。执行者已逐图看像素。

**替代关系**：前一轮行为虽过，320截图未呈现对话框，不能用作验收图；成因没有直接证明。后续等待自然动画结束、确认可见并再次检图后替代该图，未以产品绕行消除问题。焦点断言不自动证明distinct focus ring。此处44 px是项目目标，不是WCAG AA普遍要求；只签收这些确认场景。关联 UX-11/12；GS-01/12。

### RF-08 返回上下文必须检验真实历史和稳定滚动

导航候选保留账户内的搜索／分页／滚动，显式Profile／Output目标优先于记忆筛选；正确 owned history Back关闭、Forward恢复，dirty取消保稿。truly unknown历史不猜方向，“继续编辑”新建返回记录会截断Forward，须明确披露，不能宣称无损。

证据：EV-08。导航DOM回归102项和类型检查通过；15:49冻结源真实Chromium3/3，列表滚动2181→2181，详情203→203；真实窗口最小化／恢复触发trusted事件和实际身份请求，暂停时Back不留隐藏确认。早期滚轮未settled造成89 px测量差，等待12个稳定渲染帧后通过，未因此改产品源码。

unknown回退是有意披露的限制；浏览器3/3独立于既有22项组合，不累加成同一整套。源码哈希只覆盖对应时点，不能认证RF-04/05之后的修改。关联 UX-02/07/11；GS-09，具体历史合同为项目决定。

### RF-09 退出完成同样需要当前权威与归属

两个真实App、受控HTTP的DOM回归分别证明：退出已经清cookie后，旧身份核对可能重新接纳A；旧A退出401迟到可能清除B及草稿。修复重新核对当前身份，不重放退出；只有当前权威核对为401且账户代次匹配，才清理自己的工作区。离线／未知不能当已退出。已dispose的authority不再读取或清token，URL清理须以转换被实际接受为前提。

证据：EV-09。初版进一步暴露确认过期后的清理、卸载后额外读取、旧实例清新token、URL未清及误清新URL问题，分别补回归。最终34项认证测试、10文件139项关联回归与类型检查均通过、exit 0无unhandled。已纳入16:18集成源。**这些已证明竞态与RF-03首次浏览器偶发退出失败分开记录**：没有捕获后者准确HTTP序列，不推断同一根因或已修复。
