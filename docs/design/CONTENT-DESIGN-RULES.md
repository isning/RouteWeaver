# 界面内容设计规则与入门路线

2026-10-22。此前内容设计轮次的实施与证据见[该轮记录](../verification/CONTENT-DESIGN-2026-10-22.md)。本次层级补充已完成有界验收，范围与保留限制见[CH-01–04 记录](CONTENT-HIERARCHY-REVIEW-2026-10-22.md)，不以历史通过代替当前证据。规则是本项目对官方指导的综合，不是 Google 认证或任何一家公司的逐字标准。[来源目录](UX-GUIDELINE-SOURCES.md)记录链接、日期和适用边界。

## 一个核心规则

**默认界面只呈现当前任务所需的对象、动作、选择依据、真实状态与必要后果。先让结构和控件表达；每段额外说明都必须解决一个具体问题。**

不是“禁止小字”，也不是“换成更短的口号”。帮助有价值时应保留；重要内容更不能因为清爽而被藏起来。相同事实通常只在最有用的位置表达一次，但确认目标、防止误操作和无障碍反馈可以有合理重复。

## 这属于什么领域

- **UX Writing**：标题、标签、按钮、状态、错误怎样表达得准确可用。
- **Content Design**：用户此刻需要哪些信息、是否需要文字、放在哪里、何时显示。
- **信息架构与交互设计**：如果必须靠一段说明才能理解对象关系或完成操作，就应审查结构和控件，而不是继续加字。

术语职责在不同团队可能重叠，不必纠结岗位名。对本产品而言，先判断“要不要写”，再判断“怎么写”。

## 每段文字的处理顺序

1. **确定职责**：识别对象、表达动作、帮助选择/输入、显示状态、说明后果或恢复错误。不能说出职责的内容先标为候删。
2. **检查主界面**：标签和按钮是否已经表达同一事实？若没有，优先修标签、选项、字段关系和操作名。
3. **检查时机**：它是当前决定所必需，还是以后某一步才需要？将后果放到相关动作附近，不拿空态当整套教程。
4. **检查必要性**：多数人完成此步必需的信息直接可见；少数人需要的定义/背景可放具名帮助。完成任务必需的信息不能放 tooltip。
5. **检查真实性**：未知不能写成零，保存不能写成发布，交付物不能写成客户端已经生效。文案只能表达系统实际知道的事。

| 处理 | 判断依据 | 产品例子 |
|---|---|---|
| 删除 | 无新增信息，重复控件或宣传功能 | 策略组页签下再次出现“让连接各司其职”和能力介绍 |
| 改主表达 | 说明在替含糊控件解释操作 | 将有保存副作用的入口命名“保存并检查”，而非用常驻段落补救 |
| 移到决定点 | 内容必要，但出现得过早或太远 | “只登记、不连接或修改服务器”放到创建服务器提交前 |
| 按需展开 | 背景只对部分用户有用 | 术语定义、字段获取方法；使用有意义的帮助名称，不统一塞进问号 |
| 保留并突出 | 忽略会导致误判、损失或错误同意 | 撤销后重新发布会生成新链接、来源隐私、真实错误与恢复方法 |
| 改交互 | 多段说明仍不足以理解任务 | 重做选择/分组/状态呈现，而不是再加一条提示 |

2026-11-04 来源文案复核：以正向表述说明已实现的保护：平台解析、加密保存和账号使用范围。加密说明明确到保存环节，不扩大为端到端加密、服务端不可读取或跨账号后台访问能力。

## 不同文字承担不同工作

- 标题指出对象或任务，不以抽象修辞代替定位。页签已提供上下文时，不强制重复一个区块标题。
- 按钮说实际动作；必要副作用先让用户知道，但不把全部风险塞进长按钮。
- 状态是事实，不是教学段落。`草稿已保存`与指定订阅的发布/比较状态分别表达。
- 字段提示只补标签无法承担的必要格式、选择依据或歧义；不是每个字段都配一句。
- 空态给已知事实和当前下一步；没有数据、没有匹配、读取失败、未知不能合并。
- 错误说明问题及可行恢复，不拿实现术语、堆栈或“操作失败”代替帮助。

中文不机械套英文单词数、大小写或政府单问题页面布局。也不使用“每页最多几行”等跨视口硬配额代替判断。

### 选择 检查与完成的层级补充

以下是 CH-01–04 沉淀的项目规则，不是新增外部标准；修复与有界复测状态见[发现记录](CONTENT-HIERARCHY-REVIEW-2026-10-22.md)。

- **先读状态，再查身份。** 状态不能被长 ID 截断；完整稳定身份在具名、可发现的详情中可达，并关联具体位置。读取中／暂停／失败不冒充已确认缺失，不以简短标签代替真实身份，也不为显示长身份而取消大列表虚拟化。
- **披露与完成在同一决定区。** 只固定按钮、让关键披露滚走不是改善；短视口可改顺序滚动，不能遮住焦点、必填项或错误。移动完成区须保留原生表单提交关系；保留平台解析、加密保存、账号使用范围，以及文件本地读取／提交上传的时机。
- **同一决定上下文表达一次模式后果。** 不重复摘要中的同一限制，也不删除独立查看场景所需解释。新建独立链接、其他订阅不变等范围后果仍在最终确认处可见。
- **按钮表达真实下一步。** 检查与发布分开，检查通过不自动执行；阶段切换不能把双击的后续点击或持续按键当成新的发布决定。界面变更不等于用户已确认。
- **空态只陈述当前适用事实。** 零来源不讲正在合并或已保留节点；可先配置的处理能力仍可用。省略无关说明不等于隐藏操作或改变已有值。

### 集合任务的连续性与折叠摘要

以下是[集合任务审查](COLLECTION-TASK-REVIEW-2026-10-22.md)沉淀的项目规则；当前修订与验收状态以该记录为准，不沿用上一轮通过结论。

- **入口服务当前任务，不要求用户重建上下文。** 集合内“添加来源”应保留同一未保存草稿、来源顺序和两层处理；不靠一段说明让用户记住内容后离开重做。
- **分别表达保存与引用。** 来源可独立保存，加入集合只改变当前草稿；取消集合不会撤销已保存来源，也不会暗中保存配置或发布订阅。待诊断／待接受不写成已可用，更不能自动接受候选来让路径显得完整。
- **保留已知身份，不冒称数据新鲜。** 后台核对延迟或失败时，不因列表暂未包含对象而丢掉刚确认的来源名称或选择；已有身份与当前读取状态分别表达。
- **收起仍说明用途和配置，不暗示执行。** 来源行以“来源处理”说明展开内容；非零时显示已配置步骤数，包括已停用步骤。配置数量不是运行数量，折叠也不能改变值、顺序或启用状态。
- **错误可读，恢复可找到。** 窄屏恢复动作可顺序堆叠，不以侧置按钮把错误正文挤成窄列。返回父任务后检查动画结束时的实际焦点；仅按钮可点或页面未溢出不算完成验收。

### 真实状态与子任务的补充

2026-10-23新增，源于[本轮问题与拟定验收](UX-STATE-AND-EDITOR-REVIEW-2026-10-23.md)。以下是设计规则，不表示候选已合入或通过。

- **先让状态可见，再写说明。** 动态成员的关闭、全部有效连接、按条件纳入必须可区分；不能靠空字段占位或操作历史表达开关。没有权威结果时不写猜测数量。
- **“已保存”要说明保存了什么。** 来源输入已保存、导入未完成、旧接受快照仍保留是可同时成立的事实；不要统一写成未保存或完成。Cancel只影响之后尚未保存的部分，不暗示删除已保存来源。
- **审查文案符合首次与更新场景。** 没有旧快照时不用“保留原选项”；候选必须明确接受，回到父草稿不等于加入已可用来源。恢复动作说明当前下一步，不要求用户记住草稿再去另一页重做。
- **业务停用不伪装成控件禁用。** 处理步骤关闭但字段仍可编辑时，保留正常可读性；开关和必要短状态表达不执行，不整体降低透明度或补一段解释来弥补。
- **删无选择的门槛，不删决定后果。** 只有权威加载确认零目标时才直达新建；仍明确独立链接与检查/发布界限。未知、失效目标和已撤销对象不能为简洁而消失。
- **短标题需要空间，不只需要短句。** 普通步骤名被按钮挤成单字列时改布局；不要删关键身份或再缩字。无匹配用相关事实和清除搜索，不复制首次使用教程。

产品界面只呈现对当前决定有用的事实；完整测试范围、证据缺口和“未认证”等评审限制继续留在交付记录，不变成常驻产品提示。

### 整合复核后的内容补充

2026-10-23同轮补充；局部证据、四次非全绿整合结果与有界本地UX接受的限制见[UX23验收记录](../verification/UX-STATE-EDITOR-2026-10-23.md)。

- **动作名和忙碌状态各司其职。** 等待不会把“检查发布内容”变成另一个动作；可访问名称保留可见任务意义，装饰图标不混入命名，忙碌/禁用独立表达。不要为适配测试而换成模糊匹配。
- **聚合重复提示不合并不同事实。** 已知提取警告可共享一张卡；保留各自排除后果、原位置和准确数量单位。未知诊断用中性归类，不擅自解释成同一种提取情况。
- **保留事实不等于展示原始载荷。** 已知诊断的安全摘要不能退回不受信任原消息；减字和聚合不授权新增凭据曝光。未验证的未知诊断脱敏能力不能写成已保障。
- **从第一个有效状态就表达正确下一步。** 权威零目标已确认后不短暂呈现旧选择关卡；不要靠动画结束或副作用才纠正文案/结构。尚未知时仍诚实呈现读取状态。
- **既有来源不仅有名字，还有可用版本。** 暂停/无接受快照要具名可修；旧快照仍可用和最新导入失败/待审可以同时成立，不能合成笼统“不可用”或“最新成功”。间接Collection引用的修复不改父输入模式与配方；明确移除引用不能留下看似仍有效的旧物化连接，也不暗改共享配方。
- **错误去重按事实覆盖，不按语言删减。** 可信422的已保存提示与generic错误重复时可合并，但保留导入失败原因和恢复；未知422、503、409或结果不明仍如实表达，不能一律隐藏。
- **技术原因不变成用户小字。** 缓存节点、焦点时序、自动化预算和证据缺口属于验收记录；界面保留用户需要的事实、后果和恢复动作。

## 已验收轮次的修改前后与保留的事实

以下为此前内容设计轮次实施的决定；达成范围由该轮实际页面和行为证据界定，不以这张表自证成功。

| 修改前 | 修改后 | 为什么 |
|---|---|---|
| “让连接各司其职”＋能力介绍＋空态教学 | 策略组页签提供上下文；“暂无策略组”＋一个添加动作 | 删除无任务职责的层次，不只改口号 |
| “检查并发布…”旁用长句解释会先保存 | 新/未保存改动用“保存并检查”；已保存用“检查发布” | 主动作本身表达副作用；后续选择处显示真实已保存状态 |
| 去向标题、配置类型解释、字段值、结果复述、操作教学 | 字段与选项表达去向；仅适用时保留“已导入的连接尚未用于分流” | 保留可能误判的事实，去掉重复描述 |
| 普通更新重复目标名及多句不变说明 | 目标、客户端/模式各有位置；“链接不变，其他订阅不受影响”一次 | 不削弱影响范围，也不逐字段重复“不变” |
| 无服务器时讲解登记与部署整套流程 | 空态事实＋添加；登记后果在提交前可见 | 用户需要作决定时再呈现必要信息 |
| “添加并使用来源” | “添加来源”，加入配置与分流生效分别表达 | 加入可用连接不等于已改变流量去向；不以动词暗示不存在的效果 |

不可由这轮“删说明”删除的内容：来源传输/隐私、保存和发布界限、具体Output目标、恢复已撤销订阅的新链接后果、授权优先级、批次执行/停止/回滚影响、未知和失败、审阅未覆盖具体规则的限制。

不得写成“发布后客户端已生效”或“已有连接不受影响”：本系统冻结交付物，不掌握外部客户端重载时机。也不能根据Profile时间或dirty状态推断所有关联订阅都有未发布变更。

## 如何验收，避免又回到只看测试数

逐个真实状态检查：用户能否找到对象、理解按下按钮会发生什么、看清重要后果，并在失败时找到恢复动作？这是评审问题，不冒充已经做过的真人研究。

- 实际桌面/窄屏截图分别审查文字职责和重复，不只量高度或字符数。
- 删除描述后检查按钮、字段标签、可访问名称和单一下一步仍存在；不能因公共组件结构丢掉动作。
- 测试锁定保存/发布/取消、目标身份、隐私和后果等合同，不锁定装饰口号。
- 必需说明不能一律折叠；未知不能为了整洁变成成功/空状态。
- 记录源码判断、组件行为、真实后端流程、像素观察和人类理解证据的不同范围。

上一轮450项Web与15条真实任务通过，仍遗漏了内容冗余。它们证明相应行为，不证明文案已经优秀。本轮必须单独做内容评审；“Google产品水平”是目标，不是自动化分数。

## 入门阅读顺序

以下均为英文。预计时间仅为我们的阅读建议，不是网站给出的时长。

1. [NN/g：UX Writing Study Guide](https://www.nngroup.com/articles/ux-writing-study-guide/)（GS-22）：先用5–8分钟看领域地图，不必一次读完所有链接。
2. [DWP：Hint text](https://design-system.dwp.gov.uk/guidance/hint-text)（GS-17）：用5–8分钟学习哪些帮助值得常驻、哪些重要信息不能降格为hint。
3. [GOV.UK：Designing good questions](https://www.gov.uk/service-manual/design/designing-good-questions)（GS-21）：先读Add help text where necessary，练习判断该改文字还是改问题/结构。
4. [Microsoft：UI text guidelines for SharePoint web parts](https://learn.microsoft.com/en-us/sharepoint/dev/design/ui-text-for-web-parts)（GS-23）：看重复、帮助链接、错误和具体界面文字。这里的hint/ghost text指输入框内提示，不等于DWP的字段外辅助说明。

进一步可读GS-16的界面写作、GS-18的按钮/错误/对话框、GS-20的tooltip边界。GS-19是Google技术文档语气指南，不是Material产品界面的强制规范。

小练习：在一张页面截图上圈出每段说明，写出它解决的具体疑问；再选删除、改控件、迁移、保留或改交互。最后检查删掉它是否让某个真实后果变得不可见。不要以删得最多为优胜。
