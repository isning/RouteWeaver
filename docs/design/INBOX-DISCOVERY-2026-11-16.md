# 消息查找任务改进

## 任务与发现

用户要求持续从使用者角度探索各页面缺少的设计，而非只改变装饰。本轮针对消息页的一个完整任务：从已有消息中找到待阅读的额度/到期提醒，再返回列表。

基于 5242d23 源码检查，消息页只有刷新和逐条阅读。消息多时需要滚动逐个查找；未读点和状态存在，但不能直接筛选。此次不是全站视觉验收。

## 实现

- 使用现有 ResourceToolbar 和 SearchField，按标题和正文搜索。
- 全部/未读为单一阅读状态筛选，显示未读数以及总数/匹配数。
- 区分零消息、无未读、无搜索匹配；筛选空态提供直接恢复。
- 保持现有逐条阅读确认、请求失败重试、过期选择内容和刷新状态。
- 阅读后若该项离开未读列表，关闭详情回到搜索框，而非丢失键盘焦点。
- 搜索/过滤只改变本地视图，不发写请求；没有增加批量标记或删除。

## 验证与限制

本地相关消息 DOM 测试 23 项通过，类型检查与构建通过。受限宿主拒绝 Chrome Unix socket 创建，本地桌面/窄屏浏览器用例未能执行，不算通过；标准 CI 已添加 1440/390px 的完整查找、阅读、返回与无横溢出任务，结果以该提交的 CI 为准。新增截图仅使用合成数据。视觉质量仍需查看实际截图，不以测试通过替代审美判断。

## 后续页面探索

优先按用户任务继续：节点集合的预览/分页，链路配置的并行检查和重试，复杂策略窄屏编辑，备份恢复的替换文件与失败恢复。此列表是待审查计划，不声明这些页面已有缺陷或已完成验收。不要增加常驻防御性文案，也不要通过删掉实际功能来精简页面。
