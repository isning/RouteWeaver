# UX 审查速用手册

整理：2026-10-23；2026-10-24 补充读取恢复与实际候选审阅。这是 RouteWeaver 的**项目综合方法**，用于下一轮产品体验、UX 设计与建模审查，不是官方标准、Google 认证或用户研究结论。详细方法见 [UX-METHODOLOGY](UX-METHODOLOGY.md)，来源及原核验日期见 [GS 来源登记](UX-GUIDELINE-SOURCES.md)。本次只整理既有记录，未重新核验外部网页；清单不是通过证明。

## 以完整任务为审查单位

1. **定义任务**：谁要对哪个对象完成什么；从真实入口走到结果与恢复。先写模型、不变量和完成条件，再谈布局。
2. **找出阻碍**：先查错误目标、误报成功、意图丢失、不可操作，再查层级与文字。区分源码假设、实际复现、专家判断和真人研究。
3. **做最小完整修改**：优先改模型、结构和控件；必要文案就近放置，不用说明段落掩盖交互问题。
4. **复走与留证**：原任务 → 失败/取消/返回 → 相邻任务与未选对象；核对精确版本、真实渲染与键盘/触屏。分别报告通过、失败、未运行和不适用。

## 已观察问题 → 可复用决策

以下是有明确范围的专家走查或测试/浏览器观察，**不是用户研究**。修复范围、失败历史和最终版本只在链接原记录维护，不在本页复制流水账。

- **两个设备都“已发布”，真正需要更新的对象不突出** → 让比较结果领头、时间次要；发布元信息不抢状态层级。[决策与证据](SUBSCRIPTION-STATE-HIERARCHY-2026-10-23.md)
- **新增规则在未作选择时被赋予直连意图** → 在同一草稿模型中显式保留“不完整”，提交边界阻止写入；补全后仍回到原设备。[决策与证据](EXPLICIT-RULE-DESTINATION-2026-10-23.md)
- **现有规则任务前堆积来源设置，折叠又可能藏掉问题** → 渐进披露次要编辑，来源身份、有效输入状态、默认去向与恢复留在外面；折叠不改值。[决策与证据](PROFILE-SOURCE-DISCLOSURE-2026-10-23.md)
- **切换匹配方式清空输入，关系切换丢条件** → 将“改关系”“添加”“替换”分为独立动作；兼容值保留，不兼容损失需确认。[决策与证据](RULE-AUTHORING-PRESERVATION-2026-10-23.md)
- **嵌套确认关闭后焦点掉到 BODY** → 按所属确认的关闭生命周期移交焦点；在实际动画后验证，不用定时器或全局焦点拦截代替所有权。[决策与证据](PROFILE-SOURCE-DISCLOSURE-2026-10-23.md)

- **历史显示“已发布”，当前冻结凭据却不可交付；轮换后恢复只在toast中** → 分开验证历史、当前grant证明与交付，以精确owner-safe原因恢复同一Output；任务失效与视觉关闭分别处理。[决策、来源与有界证据](../verification/ROTATION-RECOVERY-2026-10-23.md)

待验证问题单独排队，不借用其他任务的通过：[managed-route 出口变更](MANAGED-ROUTE-EXIT-CHANGE-2026-10-23.md)按其记录判断隔离实现、验证与集成范围；深层规则树的窄屏可读性仍有范围限制。

## 读取、审阅与恢复：六条可复用原则

以下延续 UX-01/03/05/07–12，是**项目从实际问题归纳的方法**，不是来源对缓存、会话或合并算法的具体规定。用于下一轮评审时，每条仍须重新取证。

| 原则 | 评审问题 | 应避免的做法 |
|---|---|---|
| **任务生命周期不随后台读取结束。** 用户正在编辑、审阅或核对结果，与列表正在刷新是两件事。 | 读取延迟、失败、离线、确认缺失后，原任务、输入、身份和恢复入口还在吗？明确取消、换对象或换账户是否正确结束旧任务？ | 因列表暂时无数据而关闭表单；恢复后重置选择；迟到结果打开已经关闭的任务。 |
| **保留输入，不借缓存获得写入资格。** 已知名称和草稿可以保留；当前对象可用性与提交资格另行判断。 | 哪些依赖确实影响此动作？失败只阻断依赖它的动作吗？恢复读取会不会自动提交？结果不确定时能否只读核对原尝试？ | 把旧快照当作当前可写证明；把读取失败写成零或删除；重连自动重放写入；为无关依赖失败阻断整项任务。 |
| **展示用户实际会得到的候选。** 比较当前对象与按真实规则合并后的结果，而非仅比较上游版本或数量。 | 个人修改保留后，条件、去向、顺序与默认值到底怎么变？审阅与实际应用是否对应同一候选？ | 规则数量相同就称无变化；用模板新版本冒充合并结果；用候选序号描述当前项。 |
| **摘要不完整，不等于已知变化不存在。** 区分已确认的变化、可展示的细节和仍未知的范围。 | 明细被省略或旧侧不可比较时，已知类别变化是否还可见？有效修复候选能否独立判断？ | 把省略显示为空或相同；删掉已确认变化；用“已比较”暗示覆盖规则文件、运行状态或全部个人修改。 |
| **动作名稳定，状态独立表达。** 等待、失败与完成应可感知；装饰图标不改变动作的可访问名称。 | 等待前后还能认出同一动作吗？状态是否程序化关联且不重复播报？后台变化是否抢焦点？ | 将 loading 图标混入动作名称；只改忙碌文案而不提供可访问状态、也不保留可辨认的动作含义；多个错误区重复同一事实；网络恢复后无故跳焦点。 |
| **在动作点确认身份，而非要求记住左侧内容。** 状态、必要目标身份与后果应支持同一次决定。 | 窄屏横向滚动到行操作时，还能确认正在操作谁吗？长名、相同显示名和键盘导航能否区分对象？ | 仅证明表格可滚动、按钮可点击就判可用；让目标名在屏外而操作独自可见；用删身份换取不溢出。 |

### 用项目例子校准判断

- **模板首次使用：有界验证。** 读取失败与空列表分开，恢复保留版本、目标及绑定；本地可独立确认的连接不被无关远程读取失败阻断。重试只读，应用仍需明确动作。[证据与限制](../verification/TEMPLATE-FIRST-USE-RECOVERY-2026-10-24.md)包含 DOM、实际构建与受控 HTTP 浏览器结果；这不证明真实后端断网或发布成功。
- **模板更新：有界验证。** 同数量规则仍展示东京→伦敦及默认去向变化；以实际合并候选审阅，保留当前侧身份和已知类别变化。[证据与限制](../verification/TEMPLATE-UPDATE-REVIEW-2026-10-24.md)区分 HTTP/DOM、真实后端浏览器与像素范围；不延伸为全量门槛、部署或客户端生效结论。
- **订阅创建会话保留：功能已整合，有界验证。** 已打开的任务跨读取失败保留身份、选择与原尝试；不可用时限制写入，只读核对仍可恢复。[证据与限制](../verification/SUBSCRIPTION-CREATION-RECOVERY-2026-10-24.md)记录构建浏览器与受控发布响应的验证，不证明真实发布持久化。后续[发布不确定反馈与弹层键盘边界](../verification/subscription-publication-feedback-2026-10-24.md)也已整合并完成有界验证：保留不确定状态，合并重复报错，恢复动作保持原尝试，弹层边界保留键盘焦点。后续[重试动作收敛](../verification/PUBLICATION-RETRY-ACTION-2026-10-24.md)让原尝试只保留一个明确的“重试上次发布”动作，只读核对仍独立；新建任务不变。完整聚合验收仍未完成；局部通过不覆盖历史失败，也不能解释此前未确证的失败原因。
- **移动表格动作处身份：有界验证。** 从“滚动到动作时目标名在屏外”出发，分别核对身份与动作共同可见、窗口缩放、窄屏标题换行及版本选择。[证据与限制](../verification/TEMPLATE-BINDING-IDENTITY-2026-10-24.md)保留实际视口任务、像素与弹层定位检查；当前通过不等于全局门槛通过，也不证明此前漏激活的精确原因。

上述证据只支持各自写明的版本与验证范围，合入或交付状态仍以相应记录及交付清单为准。完整聚合验收不借用这些局部轮次的通过。

### Guideline set 来源怎样支持这些原则

沿用[来源登记](UX-GUIDELINE-SOURCES.md)中的稳定 ID、原核验日期和边界，本次没有重新访问网页，也不新增外部要求：

- **GS-09/10/11 · IBM Carbon 官方设计指导**：[通知](https://www.carbondesignsystem.com/building-blocks/core/components/notification/guidelines)、空态和加载指导支持上下文反馈、区分未知与空、局部恢复；具体任务所有权、依赖划分和写入门槛是项目决定。
- **GS-06/07 · IBM Carbon 官方设计指导**：[表格](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)与[表单](https://www.carbondesignsystem.com/building-blocks/core/patterns/forms)支持比较、分组与可理解操作；实际合并候选、当前侧编号及移动身份验收是项目适配。
- **GS-01 · W3C WCAG 2.2 规范；GS-26 · WAI APG 实现指导**：[固定规范版本](https://www.w3.org/TR/2024/REC-WCAG22-20241212/)与[可访问名称和描述](https://www.w3.org/WAI/ARIA/apg/practices/names-and-descriptions/)用于检查名称、状态、关系、焦点与重排。APG 不是新增规范，局部检查不等于完整 WCAG 符合性。
- **GS-16/18 · 官方内容指导**：[GOV.UK 界面写作](https://www.gov.uk/service-manual/design/writing-for-user-interfaces)与[Microsoft Writing style](https://learn.microsoft.com/en-us/windows/apps/design/style/writing-style)支持先改结构、明确动作及必要后果；不规定本项目中文句式，也不为比较完整性作保证。

## 每条新发现只记这些

> **任务 / 对象与不变量：** …  
> **发现与严重性：** 期望…；实际…；源码假设 / 专家判断 / 实际复现 / 真人研究…  
> **依据：** GS-ID + 来源登记中的直接链接、原核验日期；项目决策另列，不冒称来源原文。  
> **修改与代价：** …；保留…；明确不覆盖…  
> **证据与结论：** 精确版本、路由/数据、视口/输入方式、日志/截图链接；PASS / FAIL / UNVERIFIED / N/A（理由）；下一步…

新增外部来源先在[来源登记](UX-GUIDELINE-SOURCES.md)记录作者/组织、标题、直接 URL、版本/更新日或未知、实际访问日、类型、适用边界。规范性标准、官方指导、产品案例、社区检查表、研究方法、工具说明与项目综合规则不可混称。结果留在对应决策/验收记录，索引只负责找到它。

## 确认后果与批准快照（项目补充）

检查按钮旁的后果是否来自该次动作批准的同一权威快照，而不是缓存列表状态；错对象/用途的结果不能显示成功，后果未知不能猜成“不变”。点击时冻结批准内容，任务关闭/替换后只保留必要缓存核对，不重开旧的后续操作。短屏把后果与确认同处可见决定区。

这一项目规则来自[订阅后果的实际RED与有界验证](../verification/OUTPUT-REVIEW-CONSEQUENCE-2026-10-23.md)，不是外部指南对具体API结构的要求。该记录保留155/158、两个fixture修正和原超时未复现的诊断，不能据局部通过称整套绿色。

## 比较、输入更新与短屏确认（项目补充）

先用普通对象名和富变化数据观察决定质量，再用长名压力测试：结论紧邻覆盖范围；实际变化默认可读；次要详情各自命名；精确目标、真实后果与确认同组。短屏优先同一DOM顺序滚动，不靠藏后果或永久双模式换空间。可选输入刷新计数与规则比较是不同事实，缺失不等于零，不用于扩大比较结论或发布资格。

取消必须同时验证“批准立即失效”和“动画关闭后焦点有归属”；不要用立即卸载、定时器或全局拦截代替生命周期。新任务/主动导航拥有焦点时，不归还旧入口。DOM、真实后端、响应replay、真实浏览器输入、截图和客户端应用分别记账；mocked响应replay不能改称live轮换。先核对工具API/实际计算名称，再冻结typecheck和运行，清理失败与动作失败分别保留。

这是[订阅确认层级与输入刷新记录](../verification/OUTPUT-REVIEW-HIERARCHY-2026-10-23.md)的项目方法，不是Google/Cloudflare认证。来源仍按GS-07/16/26及GS-01的原始链接和适用边界理解；局部绿色不覆盖旧失败或未跑full gate。
