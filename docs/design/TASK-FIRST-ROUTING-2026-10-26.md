# 任务优先的分流编辑与发布审阅

2026-10-26。这是 RouteWeaver 的项目设计方法，适用于同一完整编辑器内的分流任务与指定订阅发布审阅；不是 Google 或其他产品的认证。当前实现的有界证据与待完成项目见[验证记录](../verification/TASK-FIRST-ROUTING-2026-10-26.md)。

## 从问题到可观察的结果

| 问题 | 项目设计决定 | 可观察的验收条件 |
| --- | --- | --- |
| 用户先理解策略组结构，才能设置默认去向或例外 | 默认先展示分流规则；保留同一完整编辑器及高级设置。不增加简单/专业模式，不替用户重写 IR | 导入只增加可用输入，不改变默认去向、规则或组；用户显式选择后才绑定目标；取消后草稿不丢失 |
| 新建策略组后，还要记住原来的规则再回去绑定 | 在默认去向或规则处打开完整策略组编辑器；以稳定规则 ID 和预期旧目标执行一次创建并绑定 | 新组只绑定原任务；目标已删除、重复或变更时拒绝误绑；其他未保存字段保留；取消不留下孤立组 |
| “被使用”容易被理解为真实流量或完整影响分析 | 区分默认去向、直接规则引用与上级组引用；审阅分别展示发布前后引用 | 能找到具体引用及其版本；间接引用不冒充直接使用，未知、部分结果和截断数量不写成零影响 |
| 文本相同或规则未变，会掩盖组成员、策略或连接设置变化 | 比较已发布冻结内容与候选内容的语义类别；对象及具体改变优先，数量按需展开。只在指定订阅审阅中折叠完整、权威且未变的分流；生成配置文本比较保持原有独立语义 | 成员、策略、连接类别变化无需打开 JSON 即可辨认；同名替换保持身份可查；未知、部分结果、截断和未比较范围直接可见；不根据文本相等擅自禁用发布 |
| 选择入口时缺少依据，补充信息又可能泄露基础设施 | 仅组合当前租户可用入口与其已授权概览，以稳定 routeId 对齐名称和当前倍率 | 同名入口仍可区分；倍率未知不默认为 1×；不推断地理位置、真实出口或健康，不展示主机、凭据和拓扑；查看信息不自动激活入口 |
| 带本地规则文件的发布，被误说成普通订阅链接 | 用已检查候选中的已接受本地资源判定配置包后果；创建与指定订阅更新均在最终决定处说明交付方式 | 检查前不承诺链接；普通订阅保留真实链接后果；配置包明确下载/导入，不承诺链接或二维码；重新检查时先清除旧后果，写入仍受目标和预览摘要约束 |
| 窄屏截图看似完整，真实打开时标题、对象或确认动作却不可见 | 按窗口宽高重排；仅表单正文滚动，保留对象和决定区。分别记录初始视口、普通滚动后视口与取景截图 | 独立打开 390/320px 场景，标题、长对象名和提交动作可达；本次弹窗可见输入/选择/按钮达到项目既有 44px 目标；取景后的图片不冒充初始可见性 |

## 必须保留的边界

- 沿用 Profile/IR/Group/Rule 与 React/Ant Design，不增加新的路由聚合、接口或框架。纯 `routing-task.ts` 集中处理有前置条件的本地变更，保留身份、顺序、未知字段及无关编辑。
- 已接受规则文件的现有版本固定值优先于目录的新版本；选择资源同时设置匹配引用与描述，不自动升级固定版本或清理其他资源。
- 语义审阅只读取允许公开给该所有者的类别与名称，不显示原始连接秘密或私有比较摘要。直接引用不是流量预测。规则文件内容和客户端运行设置不在这些语义类别的比较范围内。
- 保存、检查、发布和客户端实际应用是不同事实。指定订阅的目标、预览摘要、冲突重查、链接保持/替换及其他订阅不变的合同不因界面简化而削弱。

| 来源层级 | 可借鉴的内容 | 本项目的适配边界 |

| [Google Design：Control and Simplicity in the Age of AI](https://design.google/library/control-and-simplicity)——官方产品设计案例 | 简洁与控制取决于具体任务；熟悉的概念和适时的精细控制可以共存 | 借鉴任务组织，不把 Google Clips 的案例当作管理控制台规范；不因追求简洁删除完整控制能力 |
| [Android Developers：Adapt layouts](https://developer.android.com/design/ui/mobile/guides/layout-and-content/adapt-layout)——官方平台设计指导 | 考虑窗口宽高，用重排、容纳和展示方式变化适配空间 | Web 弹窗的断点、44px 目标及滚动方案是既有项目规则；不机械复制 Android 尺寸，也不声称平台符合性 |
| [Tailscale：Exit nodes](https://tailscale.com/docs/features/exit-nodes)——官方产品模型参考 | 区分提供出口、允许使用与客户端选择使用；实际流量仍需验证 | 只借鉴“可用不等于已选择”的清晰模型，不照搬 Tailscale 权限结构，也不以配置证明真实流量路径 |
| 固定版本 mattpocock skills：[TDD](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/skills/engineering/tdd/SKILL.md)、[Codebase Design](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/skills/engineering/codebase-design/SKILL.md)——工程实践参考 | 通过公开接口观察行为，在清晰模块接口处集中不变量，保留有意义的先失败后通过证据 | DOM、HTTP、渲染器与真实浏览器分别回答不同问题；不能用测试数量代替内容理解或易用性研究 |
