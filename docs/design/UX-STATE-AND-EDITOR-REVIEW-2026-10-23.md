## 保留的设计与验收合同

### 动态成员状态必须可见且稳定

在同一权威有效连接集合下，可见配置应足以区分动态纳入规则，不能由清空字段的历史决定。`dynamic` 缺省或null表示关闭，`{}` 表示开启且不限定条件，非空对象表示开启且有条件。打开旧对象不能迁移这三种含义；清空最后条件仍保持开启，关闭只能由明确操作完成。本轮实现明确采用关闭即清除条件、再次开启为全部的规则；有条件时在关闭决定附近显示后果，不暗存另一套持久化语义。

“全部”的范围是当前配置物化后的全部有效连接，包括集合处理结果与已选平台连接，不是用户库存的全部来源。固定成员与动态成员保持相加、去重；切换不得删除固定成员或改变默认去向。没有权威结果时不显示猜测人数。自动纳入是配置选择规则，不代表来源自动接受、Output自动发布或客户端自动重载。

### 在父任务内完成来源审查

父编辑器继续拥有未保存的名称、稳定引用、有序来源、来源处理、合并处理及 Profile 规则/组。子任务复用现有导入与候选审查，不另造第二个确认模型。首次导入的候选必须明确接受后才能作为本次可用结果返回；取消、拒绝、稍后处理都不能暗中附加、保存父草稿或发布。

已独立保存的来源不会因取消父任务而删除。保留具名的继续审查入口；首次候选没有旧快照时，不用“保留原选项”暗示旧数据存在。已接受诊断可以继续解释提取后果，不能仅因有诊断就强迫再次接受。真实使用条件、当前候选身份和接受结果由权威响应确定，不以 toast 或 `diagnostics.length===0` 猜测。

### 四个保存层次分别表达

| 层次 | 含义 | 不能冒称 |
|---|---|---|
| 本地未保存编辑 | 此次尚未提交的输入或父草稿变化 | 已持久化、已发布 |
| 已持久化来源输入 | 服务端已保留定义和 revision，即使此次导入失败 | 已有可用的新连接 |
| 已接受来源快照 | 明确接受后的连接版本；失败刷新可能仍保留旧版本 | 当前输入已成功导入、所有引用都已发布 |
| 指定 Output 冻结发布物 | 对这个目标完成独立发布 | 兄弟 Output 已更新、外部客户端已生效 |

422若明确返回同一来源及新revision，使用实际提交载荷建立“已保存输入”基线，不用脱敏响应覆盖本地字段；之后再修改的部分才是未保存编辑。短状态可表达“输入已保存，导入未完成”，旧快照保留或新来源尚无可用快照的后果按实际情况就近说明。Cancel只取消当前尚未保存部分，不回滚已确认写入。

超时、断连或409不能一概写“未保存”或“原选项保留”。先只读核对当前来源，不自动重发接受或重新抓取。当前可用状态也不能伪造证明“刚才那个候选已由本次操作接受”的回执。

### 富编辑器分别满足语义 操作与扫读

- 停用处理不等于禁用编辑：保留活动字段、操作和焦点的正常对比度，不对整个可编辑容器降透明度；用已有开关及必要的短状态表达不执行。
- 披露、重排、删除分别有独立的键盘行为；从真实 Tab 顺序执行 Enter/Space，每次只产生预期动作。重排后保留对象身份、步骤归属和合理焦点；不通过全局吞键掩盖组合问题。
- 窄屏先安排标题/状态，再让操作簇换行，不靠挤窄标题给大按钮腾位置。先测普通名称，再测长名、同名和大量数据；不删身份或取消虚拟化来换表面整洁。
- 同时看实际命中区域、间距、截图和层级。44px是项目舒适目标；WCAG 2.5.8另按24×24 CSS px及例外判定。没有溢出、脚本能点、组件库自带支持都不是完整验收。

### 只删除已证明没有选择的门槛

仅当当前权限范围的权威读取成功且确认零关联 Output、没有不可用的指定目标时，才直接展示清楚标识的新订阅表单。读取中、暂停、失败、旧缓存或目标失效不能触发该简化；已撤销但仍存在的 Output 不能被悄悄当不存在。一个或多个既有目标仍保留明确选择。

新独立链接的后果、目标/模式、检查及最后发布决定不删除。双击、持续 Enter、迟到读取及重试不能跨过独立决定或重复创建。优化的是无替代项的选择，不是减少用户控制。

## 逐项签收所需证据

以下保留完整验收合同，不单凭清单打勾声称执行。已完成的局部范围和剩余缺口见UX23-C01–C13、D01/D02及Q01–Q04；每项签收仍需实现位置、冻结构建、独立复核人、实际结果和边界。

1. **成员语义：** 缺省/空对象/有条件旧值，分别清空通用条件与来源条件；明确开关、固定+动态去重、零匹配、集合/平台输入范围、保存重开、权威预览、指定发布及未选兄弟 Output 对照。
2. **来源连续性：** 两种真实完整配置导入；Collection 与富 Profile 父草稿保留；接受/拒绝/稍后/继续审查、键盘返回焦点；成功后仅附加一次稳定ID，无父对象隐藏写入或自动发布。
3. **持久化反馈：** 创建和编辑422、旧快照不变、重试同一身份、已保存后再编辑/取消；结果不明与过期候选分别验证，不把提示文案测试当结果核对。
4. **富编辑器：** 从页面入口自然 Tab、Enter/Space的独立操作、首尾重排、同名对象焦点、320/390/桌面截图；在真实合成背景上复测活动文字和必要控件状态/焦点，而非只删除CSS声明。
5. **首用简化：** 已加载零/一/多目标、加载/失败/暂停/过期数据、不可用指定目标、已撤销目标、快速完成后的跨阶段手势；显示表单不产生写入。
6. **整体验收：** 最终整合源的适用回归、后端任务和独立像素/内容复核；原问题与候选新增回归分开记录。不累计不同时点的局部测试数来冒充一次全套通过。

本轮关闭条件是已确认高影响缺口经最终集成复测关闭，主要及失败恢复任务完成，剩余边界清楚且不影响所声明的范围。真实用户无提示研究、完整WCAG、多浏览器/设备及生产运行仍需独立证据，不能因本轮修复通过而补写成功。

## 同轮整合新增的方法

- 菜单隐藏不保证交互结束；按合同验证节点生命周期、关闭原因和后续焦点，不把所有折叠草稿都销毁（UX23-C05）。
- 动作名在等待中保持可识别，忙碌独立表达；正确零目标分支从首次权威就绪渲染开始（UX23-C04）。
- 聚合已知诊断保留事实/原位置/计数单位，未知诊断不乱归类；不为恢复详情新增原始敏感消息展示（UX23-C06）。
- 分开测每步响应与完整任务总预算；旧夹具迁移保留业务意图，单项未复现不抹去历史失败（UX23-C07/C08、D01/D02）。

详细复用规则见[方法第15节](UX-METHODOLOGY.md#15-整合失败如何转化为方法-而不是放宽验收)。第二轮全套已失败：Web680/706、Vite-dev浏览器59/64；其历史记录保留。C09可信422去重已有17/17聚焦和1条真实390px任务验证，C10具名原位恢复和显式移除旧物化连接已有13/13 DOM与3/3真实任务验证；之后14px文字修订已在Q03三条真实任务及320/390新图中复核。统一DOM预算政策边界已验，但Q03整套仍711/728且另有3个未捕获异常，浏览器72/74。Q04终态为Web724/728、浏览器71/74；独立fault-contract1/1与本地UX有界接受另列，不抵消可靠性失败；旧接受快照可用性不套用新导入ready条件，换lane不抹掉dev失败。
