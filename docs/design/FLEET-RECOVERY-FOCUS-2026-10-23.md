# Fleet 恢复反馈与同会话焦点连续性

2026-10-23。实际界面、受控 HTTP 与专家像素审查形成的有界决策，不是真人研究、全套通过或完整无障碍符合性结论。八文件生产/测试修改已于15:57:12 UTC按批准清单精确合入；集成收据仅证明对应字节合入，不扩大验证范围。

## 问题与决定

- 长表单的创建失败放在页首，用户停留在末尾创建动作时看不到。单一错误现在随恢复阶段归位并描述对应动作：预览错误在预览旁；保留审阅的创建错误在创建旁；409 清除审阅后在预览旁。不复制错误，不自动滚动；受控夹具的 `Plan rejected` 不代表生产错误文案已全部本地化。
- 创建期间原表单保持 inert，操作状态在其外可访问。只有被本次操作停用的精确动作拥有焦点时，才接续到该状态；焦点移到关闭控件或用户主动选择其他控件时，迟到失败不得抢回焦点；Fleet pending 期间仍阻止关闭，不表示此时弹层已被关闭。pending 状态增加局部 8px 留白，而非给所有内容增加间距。
- 首次几何断言通过仍留下贴底状态，专家像素审查未接受。最终实际截图与测量共同检查状态、错误和恢复动作：pending 文字在手机底边保留约8.14px；错误与动作实际矩形严格处于视口内。不同状态分别判断，不把一个余量推广成通用阈值。
- 普通 Ant Drawer 和原生 dialog 均可在 Tab 边界离开 document 焦点；这不证明 Fleet 焦点陷阱。但返回后的例行会话复核会使工作区 inert，丢失离开前任务所有者，是另一个已观察问题。
- SessionBoundary 只接续已确认的 Tab 离开：精确工作区、账户 epoch、会话 generation、真实 window departure 和例行 BODY-entry 复核；恢复时目标仍须有效。新焦点/指针、身份或会话变化、隐藏/离线/错误、目标失效撤销一次性恢复。没有通用焦点历史、认证绕过、定时器或依赖补丁。

## 证据边界

- Session 相同19项任务与类型检查通过；实际 Chromium 验证可信键盘离开、返回、复核后恢复原状态，再正常 Shift+Tab 到关闭。只覆盖测得的 Tab 序列，不声称任意 Alt-Tab。
- 最终反馈布局：类型检查通过；聚焦 Fleet DOM **4/5**，owned409 原10秒时限失败仍保留，具体操作阶段未知。另行授权的新构建与**五项实际浏览器任务通过**；不合并成整套绿色。
- 浏览器采用受控 HTTP，AX/事件轨迹不等于读屏语音、原生后端应用或真实部署证据。冻结的几何断言含2px容差，但接受依据为实际记录的严格入视口矩形与截图，不以容差接受裁切。
- Ant Drawer 继承的瞬时背景 focus 事件仍是独立设计系统限制；稳定终态在对话框内不证明原生等价或完整模态符合性。此前完整 Web 非绿结论不被此轮覆盖，P2 发布结果核对也另行验收。
