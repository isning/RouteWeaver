## 一个目标布局

```text
我的订阅                                      新建分流配置
搜索配置或客户端订阅    配置范围（需要时）    当前筛选与结果数

配置 A                 已保存草稿信息          编辑配置 · 更多
  Laptop  客户端 · 输出方式 · 发布状态 · 时间   获取订阅 · 检查更新
  Phone   客户端 · 输出方式 · 发布状态 · 时间   获取订阅 · 检查更新
  新增客户端订阅

配置 B                 尚无客户端订阅          继续配置

选中的订阅详情：冻结发布内容／草稿比较／访问管理
```

- 以 **Profile → 多个独立 Output** 的一份关系清单承载获取、编辑、检查与管理。移除清单上方重复的“首个 Output 概览”；摘要跟随用户选中的 Output 展开。保留现有侧栏任务分组，不进行无依据的全站重排。
- 配置标题表达可编辑草稿，订阅行表达独立发布物。不要把“最后保存”与“最后发布”时间相减来生成“有待发布修改”；配置层也不合成所有 Output 的比较结果。
- 列表使用已存在的发布 metadata。仅检查当前选中或展开的 Output，按现有 `/status` 的 `draftComparison` 展示正在比较、一致、有变化或无法比较。**不得为了填满状态列而逐行编译全部 Output。** 输入变化后沿用真实依赖失效和重新检查合同。
- 获取是已发布 Output 的直接任务；编辑属于共享 Profile。行内“检查更新”保留明确 Output 上下文。轮换、撤销、复制等低频能力可归入具名菜单，但不能删除。
- 小数据不展示空筛选仪表盘；大数据提供搜索、活动范围和分页或等价的有界列表。配置与关联订阅的身份不能因分页丢失，名称相同也用真实 ID 定位。
- 初次为空给一个“设置订阅”入口；筛选无匹配给清除筛选；读取失败给重试；未知不是零。Profile 读取失败时，仍可读取的 Output 保留独立获取与管理入口。

## 同一编辑器中的决策顺序

1. **识别编辑对象。** 顶部保留配置名、当前保存状态、关联订阅数和主操作“检查并发布…”。一条状态说明即可；关联订阅明细按需查看。必要后果仍放在决定点，不改成更多警告段落。
2. **选择连接并看见流量行为。** 主编辑区同时显示已选输入及权威处理结果、当前默认流量行为。将现有默认行为字段移到主任务位置，不创建第二份字段或第二套编辑器。规则、策略组、运行设置仍在同一草稿中按需展开或进入对应段落；必要错误不得藏起。
3. **明确意图，不替用户决定。** 添加来源后保持当前路由不变。若无规则且默认直连，准确显示“当前所有流量直连，导入连接尚未用于分流”，并提供定位到流量选择的下一步。用户可明确选择某连接或策略组，也可保留直连、拒绝连接；不自动建组、改出口或套代理规则。存在 native override 时不推断实际流量；nodes-only 说明不含分流，不要求虚构一条路由。
4. **检查并选择具体发布物。** “仅保存草稿”不发布。检查流程需要保存时，先明确这一保存边界；保存失败保留输入且不继续检查旧草稿。来自 Output 的入口可预选原目标；来自配置的入口明确选已有订阅或新增，零关联也不静默新建。已有 Output 保留自己的 target/mode；新订阅才选择客户端与输出内容。Profile 的 target/version 仍保留草稿诊断、原生覆盖及新订阅默认值的用途，准确标注，不伪装成所有订阅的客户端选择器。
5. **审阅后发布并取得结果。** 在一个连续任务中完成目标、权威检查、后果确认、执行和结果。取消审阅不会撤销此前已完成的草稿保存。发布成功后同一 Output 的获取入口持续可达；创建不多建，更新不换身份。

首次使用验收必须用**非零节点**：导入至少两个可区分的 synthetic 连接，明确选择其中一个或一个组作为默认出口，可再加一条规则；检查生成产物的路由意图并取得指定 Output 的交付内容。另走一条用户主动保留直连的路径。只取得链接不宣称外部客户端已导入、可连或 VPS 已生效。

## 发布审阅的信息合同

优先级固定为 **目标 → 已知变化 → 影响范围与后果 → 确认动作**。技术配置保留但默认折叠。桌面与窄屏使用同一比较语义，不用两份长摘要让用户记住上文。

| 信息 | 展示规则 |
|---|---|
| 目标 | 配置名、Output 名、客户端、完整或纯节点，以及新增或更新。滚动时仍有可理解的目标摘要和确认动作。 |
| 已知变化 | 权威冻结摘要与候选均支持的字段，显示同一行前后值，例如“未匹配流量：直连 → 拒绝连接”；只变化的字段优先。数量不能冒充完整规则 diff。 |
| 无法比较 | 历史摘要缺失、native override 或详细规则语义未覆盖时，明确摘要覆盖范围；保留真实冻结文件与候选技术预览。不得用当前草稿补写历史，不因数量相同声称无变化。 |
| 链接后果 | 普通更新保留原链接；重新发布已撤销 Output 会恢复访问并生成新链接；新增产生独立链接。只更新所选对象，其他 Output 不变。 |
| 检查与恢复 | 使用现有 output-update scope、digest、失效及授权合同。候选变化重新检查；结果不确定沿原 identity/receipt 核对或重试，不重复新建。 |

若需要完整的复杂规则语义差异，必须另有权威、可脱敏的冻结数据合同，不能前端猜测。本轮在现有摘要覆盖范围内做到诚实可读即可，不把新增后端 diff 引擎作为视觉简化的隐形前提。

线路进度复用同一信息层级：明确线路与用户、紧凑列出授权／入口／应用的独立证据、突出有据可依的下一步。保留 Line 与 Path 的共享关系和各自身份，不能合成无依据的绿色“就绪”。

## 旧入口与范围迁移合同

| 入口或事件 | 必须保留的行为 |
|---|---|
| `#subscriptions` | 进入同一关系工作区；无显式 Output 时不把数组首项当成用户的当前目标，也不发起写操作。 |
| `#profiles` 与 `#outputs` | 保留可直接访问的兼容入口，分别聚焦配置或客户端订阅的同一工作区视图；相关能力完整，不另造发布逻辑，不丢 query。 |
| `profile` / `profileId`，`output` / `outputId` | 继续接受现有别名并按稳定 ID 解析。有效配置仅限定其范围；有效 Output 聚焦准确对象。只有 authoritative Output 关系可用于显示归属，不能由显示名猜测。 |
| 配置与 Output 同时指定 | 校验二者真实归属；不匹配保持显式错误范围，不切到其他对象、不新建、不发布。 |
| 未知、无权、已撤销或读取失败 | 保留所请求范围和具体可知状态；**未知 Output 绝不自动选择另一个**。已撤销不等于不存在。读取失败不能自动扩大到全部对象。 |
| 清除范围 | 用户明确清除 Output 选择后，仍保留当前 Profile；更改或清除 Profile 按既有合同解除其旧 Output 子范围，并说明新范围。不可用状态提供具名清除或返回入口。 |
| Back、Forward、query-only 和内部导航 | 使用既有全局／局部脏编辑守卫。取消保留完整 URL 范围、输入及编辑身份；接受一次放弃后完成原动作，无第二次确认或旧编辑器残留。 |
| 筛选、分页、展开和迟到响应 | 只改变展示，不改保存内容、发布目标或授权；旧范围响应不覆盖新范围。回到列表保留合理查询和位置，显式深链优先于遗留选择。 |

## 不可删除或弱化的能力

- Profile 独立保存与复制；零、一、多个 Output；Output 的 target/mode、冻结产物、token、发布时间、独立更新、轮换、撤销、重新发布与交付授权。
- 来源的独立保存、导入隐私说明、候选更新复核、部分解析决定、失败保留；“添加并使用”不等于保存 Profile，不等于发布，也不改变路由。
- Source／Collection／平台入口及内置连接的既有合同；有序处理、去重、过滤、重命名；有效连接由权威预览提供；失效引用可见且不自动替换。
- 策略组、嵌套引用、完整规则与资源、运行设置、目标版本、原生覆盖、JSON 编辑及恢复；不以少按钮为由删除能力或引入简单／高级模式。
- draft/check/publish 的独立边界、冻结摘要真实性、保存失败保护、发布 fence、重复提交与结果不确定恢复；无时间戳推断“待发布”。
- 脏编辑、来源与 JSON 关闭保护、自然 Back/Forward、query-only guard、键盘／焦点／缩放、移动发布至少 44 px 的项目触控标准。
- 线路／路径／实例的独立身份，用户授权／凭据／实际应用证据，批量目标与阶段；不默认全选、不跨路径扩围、不删危险确认。

## 本地验收矩阵

下列是拟执行数据与通过条件，**不是已通过记录**。同一最终构建分别记录源码、DOM、真实浏览器与人类观察的证据，不把数量相加成为体验评分。

| 场景 | 最小证据与通过条件 |
|---|---|
| 小数据 | 0／1／2 份配置，各有 0／1／2 个 Output；两客户端采用不同 target/mode。第一视口可识别工作对象、关联发布物与下一步；无重复首项概览，零关联配置仍可编辑。 |
| 多配置与多链接 | 25 份配置、总计 100 个 Output，其中一配置有 20 个链接；长名、重名、撤销、孤立引用混合。搜索、范围、分页和管理均可用；不为列表自动编译所有 Output。测试规模是本轮 fixture，不是产品容量声明。 |
| 真实意图 | 非零连接的首次导入、明确选择出口、规则与组、发布并读取正确交付产物；另测主动直连、nodes-only 和 native override 的正确表达。不自动改变流量策略。 |
| 冻结与变化 | 两 Output 中只更新一个，另一个产物、token、metadata 不变；仅保存、接受来源更新和集合更新都不自动发布。状态用权威比较，不看时间戳猜测。 |
| 审阅覆盖 | 默认行为变化、规则数量相同但内容不同、缺旧摘要、已撤销、检查过期、结果不确定。没有依据的详细差异保持未知，确认不丢必要后果。 |
| 连续性 | 三个旧入口、有效／无效／不匹配 scope、直接访问、Back/Forward、取消／接受放弃、失败重试、重复点击、迟到响应。身份、值、权限和原任务均符合上表。 |
| 状态与布局 | 初次空、无匹配、加载、失败、未知分别取证；1440×900、1280×720、390×844，另测 320 CSS px 重排与 200% 文字缩放；键盘完成关键任务，焦点与必需错误可见。 |

先验证一条完整首用任务和一条双 Output 更新任务，再扩展矩阵；最后按项目既有资源约束串行完成完整 Web、Go、类型与构建门槛。新 UI 不继承旧构建的通过结论。截图只引用原文件或新本地证据，不重新上传原图。

## 质量门槛与仍缺的人类证据

新增方法参考：Kerry Rodden、Hilary Hutchinson、Xin Fu，*Measuring the User Experience on a Large Scale: User-Centered Metrics for Web Applications*，CHI 2010，Google Research。[官方条目](https://research.google/pubs/measuring-the-user-experience-on-a-large-scale-user-centered-metrics-for-web-applications/)；[官方作者 PDF](https://research.google.com/pubs/archive/36299.pdf)。本轮核验日期 **2026-10-22 UTC**。这是研究方法，不是规范或认证。HEART 关注与目标相关的用户指标，Goals–Signals–Metrics 从目标推导信号和测量；任务成功可考察有效性、效率和错误。选择适合本任务的维度即可，指标不能替代形成性用户研究。不复制或分发论文。

本轮本地门槛由项目制定，不冒称论文的强制要求：

| 目标 | 需要观察的信号 | 记录方式 |
|---|---|---|
| 找到正确对象 | 不需讲解内部模型，就能找到指定客户端并说清共享配置与独立订阅 | 任务是否完成、首次选择、错误目标尝试、求助与回退；区分代理走查和真实人类记录。 |
| 得到有意选择的流量结果 | 导入后能主动选择或保留路由，并知道发布到哪个客户端 | 实际选择与产物对应、任务完成及误发布／意外新增次数；不把“有链接”当“流量正确”。 |
| 理解并恢复变更 | 能解释保存与发布的区别，发现审阅覆盖不足，并在中断后继续同一对象 | 理解回答、恢复结果、必要与冗余决定；任务时间只有实际测量后才报告，不预填改善比例。 |

**本地候选通过条件**：上述工程与浏览器矩阵完成；没有未解决的错目标、静默改路由、错误成功、数据丢失或关键动作不可达；独立审查者能沿任务找到对象、意图和结果，无需源码解释。代理／启发式审查仍不能标成人类易用性验证。

**用户体验结论仍待证据**：目前没有真实目标用户的无提示任务观察、主观易用性感受或可靠效率基线。可先完成授权范围内的本地迭代和独立审查，不因此反复打断用户；不得将这段缺口写成已测任务完成率、节省时间或“已达 Google 水准”。后续人类观察需要记录真实样本、任务和失败，再决定继续改哪里；不以更多自动测试替代这一层。
