# 规则编辑：保留用户意图，而不是重置表单

2026-10-23。当前为持续打磨中的局部修正，不代表整体产品验收完成。

## 实际问题与本轮范围

通过公开 ProfileEditor 界面的 DOM 操作复现：

- 已填写 `chatgpt.com`，将完整域名切换为域名后缀后，输入被清空。
- 已有两个嵌套条件，将全部满足（AND）切换为任一满足（OR）后，条件被替换成一个空输入。

修正仅保留可兼容转换中的已有内容：完整域名与域名后缀之间保留输入；AND 与 OR 之间保留全部子条件。用户选择的新匹配语义仍然改变，不冒称语义等价。规则身份、顺序、去向不变；不保存或发布其他对象。后端校验仍然有效，不把保留的无效输入当作有效配置。

未修范围：叶子与组合条件之间、多个条件与 NOT 之间的转换仍需单独设计。不能把这次兼容转换修复称为全部表达式编辑无损，也未新增服务预设或第二套简单模式。

## 检查证据

- 修正前：两个公开界面测试分别失败，分别观察到域名为空、两个子条件变成空条件。每次仅运行相应新案例，其余案例未选择，不算通过。
- 修正后：两个案例分别通过；独立复核后补充反向转换、独立期望值与相邻规则顺序断言，整个 profile-intent.dom.test.tsx 的 13 个案例通过；TypeScript 检查通过。未调整断言、交互超时或重试次数。
- 测试操作实际选择器并点击保存，通过提交的公开 HTTP 请求观察规则身份、条件和去向。不调用 MatchEditor 私有函数。
- 这些是隔离候选的 DOM/类型证据，不能代替整合后的真实浏览器、可访问性或应用全量验收。整合与后续浏览器结果另行追加。

## 可复用的规则

1. 切换选项不是清空输入的授权。先判断哪些内容仍然有意义，再决定需要用户明确替换的部分。
2. 改变条件关系与丢弃条件是两种操作。不能把后者藏在前者里面。
3. 不用服务品牌掩盖不明确的匹配范围。ChatGPT 网站域名规则不等于完整 ChatGPT 应用覆盖；共享第三方域名尤其不能盲目纳入专属流量。
4. 同一结构化规则模型服务普通任务和复杂任务；无法无损表示的内容保持可见和可恢复，不偷偷转换成简化模型。

## 第二轮候选：添加、关系与替换各自表达一种动作

此节接续上文首轮未修范围；候选未自行合入规范工作区，不代表整体产品验收。

### 普通任务与统一界面

从已填写的域名后缀开始，点击「添加条件」，填写需要排除的子域名，再在该行的「条件操作」中选择「不匹配此条件」。原输入保留，界面展示「全部满足」下的原条件和「不匹配以下条件」。不要求先理解树结构，不增加简单／专家两套编辑器，也不靠常驻小字解释数据丢失。

- 单个条件添加条件：以原条件整体作为第一个子条件，新增一个空条件，关系默认「全部满足」。单个 NOT 同样整体保留，不移除原否定。
- 已有 AND／OR 添加条件：只追加新条件；切换「全部满足／任一满足」只改变关系。
- 「不匹配此组」包住完整的现有组，不拿第一个子条件冒充整组，也不分配或简化否定。「取消不匹配」是明确的语义变更；如果外层还有附加字段，先确认移除后果。
- 叶子的选择器只选择匹配字段；组的选择器只选择条件关系。不再把布尔结构与字段类型混为一次“切换方式”。不兼容叶子类型，以及组合条件改为叶子，采用明确替换确认。只有规范空叶子可直接换类型。
- 一个节点只用一个上下文菜单承载次要动作。已有可见「添加条件」按钮时，菜单不再重复该入口。
- 390px 下字段类型与完整输入上下排列；保留现有字号，避免域名被两个半宽控件挤断。否定范围与组关系通过结构显示，不增加解释段落。

### 保留与生命周期边界

确认前不修改草稿；取消／Escape 不改变输入、dirty、规则身份、去向或顺序，焦点返回原控制。确认后聚焦新的输入。上下文菜单选中动作后关闭；但关闭动画期间菜单仍占据组件库的 Escape portal 栈。真实事件轨迹确认焦点与首个 Escape 均在确认框内，所以确认框只在自身 capture 阶段处理取消键（忽略输入法组合事件、先清空 pending 再关闭），不使用全局键盘覆盖。重复开启不能叠加确认；所属表达式更新或编辑器卸载时销毁旧确认，避免过期回调覆盖新草稿。

原始 JSON 的应用只作浅层结构检查，因此输入不能被假定为有效 MatchExpression。已知布尔操作符也需要真实数组、可读取的直接子节点与正确 NOT 元数；超过领域现有128层深度边界、对象类型的操作符等不继续解释。无法表示的结构显示为已保留的未支持条件，允许明确替换；可读取操作符的对象在添加时保留整个原始对象，不把字符串当成子数组展开。不可读取操作符／超出深度的节点仅提供明确替换，不添加无法访问的新空条件。已知叶子兼容修改仍保留额外字段和未展示的 children。

这里承诺的是本地草稿和提交载荷保留。Go MatchExpression 只声明 op/value/children，HTTP 解码使用 DisallowUnknownFields，因此额外未知字段会被后端拒绝；没有宣称未知字段可在后端往返持久化，也没有放宽后端校验。没有新增表达式历史缓存、架构框架、API、数据模型或发布动作。

### 标量条件的可逆匹配关系视图（2026-10-23）

前面的专家任务走查发现，普通“保留 chatgpt.com、排除 private.chatgpt.com”需要寻找重复的省略号，而且一个否定条件额外占用一层。这是源码与实际任务走查发现，不是用户研究结论。现在同一套编辑器把可表示的标量条件排为「字段／匹配或不匹配／值／条件操作」；仍只有一个「添加条件」。用户先保留已有域名，添加并填写另一个条件，再直接选「不匹配」，不用先理解或创建 NOT。组关系仍明确选择全部满足／任一满足，既有 AND 默认值不变。排除意味着本规则不匹配，继续后续规则或默认去向，不自动为该域名指定机场、直连或拒绝。

仅将无附加属性的 `{op:"not", children:[leaf]}` 显示为负向标量：外层只能有 op/children，恰好一个已知标量叶子，叶子 value 为字符串或缺省，children 缺省或真实空数组，且遵守既有128层深度边界。叶子附加字段仍随完整对象保留。正向改负向包住整个叶子，负向改正向返回原完整叶子；仅改变展示不会创建dirty或重写树。兼容字段修改在内部叶子上保留属性；不兼容替换仍确认实际内容损失，并保留已选否定关系。规则ID、去向、默认去向及其他规则顺序不变。

附加字段的NOT外层、NOT(组)、双重否定外层、非空结构children和未支持结构继续使用既有树视图；不自动简化、分配否定、丢弃外层字段或创建历史缓存。标量行不再在省略号中重复否定动作，组的完整否定入口不变。匹配关系的公共可访问名称为「条件匹配关系」；视图在正负切换中保留控件身份，不新增全局焦点处理。

字段仍称「完整域名／域名后缀」，不把后缀笼统改称“域名及子域名”，也不自动移除前导点。Mihomo官方DOMAIN-SUFFIX示例包含根域和以点分隔的子域；sing-box迁移说明区分非点前缀与历史点前缀行为。后端按现有值转发，本次不修改语义。官方来源（查阅2026-10-23）：
- https://wiki.metacubex.one/config/rules/#domain-suffix
- https://sing-box.sagernet.org/migration/#domain_suffix-behavior-update

这里也不宣称单个chatgpt.com规则覆盖产品全部依赖域名。未知属性仅承诺本地草稿／提交载荷保留；后端DisallowUnknownFields仍会拒绝它们。
