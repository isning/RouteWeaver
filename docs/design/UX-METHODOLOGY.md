## 1. 目标和证据分层

目标是**一个完整界面里降低理解负担**，而非按能力分成简单/专业两套产品。这是用户/项目要求，GS-05 提供参考但不强制这一架构。Google 产品的清晰性是方向，不是认证；不能虚构任务完成率、节省时间或认知负担下降百分比。

每条结论标明它属于：①来源原则；②项目决定；③已观察问题；④有证据的修复复测。源码存在、DOM 测试通过、真实浏览器可操作、视觉合格、真实部署生效是不同结论，不能互相替代。

## 2. 工作流程：任务与领域关系 → 状态与跨入口一致性 → 信息层级 → 验证

**减少隐藏决策，而不只是减少点击。** 把五个页面合成一个页面，如果仍需用户猜“当前改的是草稿还是发布物、会更新哪条链接、是否已经生效”，并没有完成 UX 简化。明确危险对象、影响范围和发布后果的确认不能为少一步而删除。以下顺序是本项目综合方法，不是官方设计系统规定的实施顺序。

1. **先画用户任务与领域关系**：谁想完成什么，作用于哪个对象；列出一对多/共享引用、稳定身份、权限所有者、生命周期和权威数据源。不要先按数据库表分菜单，也不要因一个工作台就合并不同身份。
2. **写状态转换和不变量**：入口→编辑→检查→确认→执行→结果→恢复；区分保存草稿、冻结发布、计划、运行观察。每次转换写清改变/不改变哪些对象、证据何时失效、失败输入如何保留、结果不确定如何核对，禁止以新建对象代替身份保持的重试。
3. **验证跨入口一致性**：从列表、详情、深链、返回/前进进入同一对象，动作含义须一致。入口可以预选明确目标，不能暗中决定“更新现有”还是“新增”；一对多场景至少用两个可区分目标测试不受影响的另一对象。
4. **再设计信息层级与文案**：把“我在改什么、将影响谁、下一步是什么”置于决策点；按任务分组、将技术详情渐进展开。术语反映证据：已发布不等于当前草稿，计划不等于生效，未知不是完成。折叠仅改变展示，不能静默改变值或必填规则。
5. **建立设计决策记录**：关联 GS 来源 ID；写明选择、替代方案、冲突与代价。来源原则只解释理由，不凭参考产品为本产品认证；产品语义不明时先明确合同，不以外观或组件库默认行为代替判断。
6. **先验证整条任务，再补局部证据**：覆盖零/一/多关联、成功、失败、权限、无数据、未知、迟到响应、重复操作和离开恢复。运行界面记录构建/路由/数据/视口/输入方式/期望与实际/截图或 trace；区分 mock 浏览器、真实后端流程和真实部署观察。
7. **按风险修复最小完整流程**：错误目标、误报成功、数据丢失、关键操作不可访问优先于装饰。保留身份、权限和已有发布 fence；尽量记录先失败后通过，并复测原任务、相邻共享组件及未选对象。不为绿色结果删除断言或随意延长交互等待。
8. **分别交付状态与缺口**：实现状态和 PASS/FAIL/UNVERIFIED/NOT APPLICABLE 分开；后者必须说明证据范围，NA 给理由。完整测试数量不证明任务可理解，历史通过不签收新模型/新构建；有界通过、未知和未支持项分别报告。

### 内容设计是独立验收项

[内容设计规则](CONTENT-DESIGN-RULES.md)规定每段文字须有任务职责，再判断删除、改主表达、迁移、按需披露、保留或改交互。不能用“没有溢出”“按钮能点”“测试全部通过”替代可理解性检查；上一轮完整功能回归仍未发现口号和重复解释的问题，是这项门槛需要独立建立的实际依据。

同一界面至少检查空态、有数据、错误/未知、普通与危险确认：无需靠说明猜对象；动作名称诚实；重要后果在决定时可见；隐藏帮助不承载完成任务的必要信息。减字后重新走任务，防止把信息负担转成猜测负担。不为“清爽”删除权限、来源隐私、恢复新链接和比较覆盖范围。

#### 层级修改也要验收状态转换

CH-01–04 的[内容层级审查](CONTENT-HIERARCHY-REVIEW-2026-10-22.md)补充了以下方法；它们是项目综合判断，修复是否通过仍以该轮证据为准。

- **先看默认状态，再看脚本能否到达。** 记录截图是否已滚动或被确认框遮挡；按钮经脚本定位后可见，不证明初次打开易于发现。编辑器内容应在遮挡关闭后直接复核。
- **把身份、状态和位置分别检查。** 窄屏不只查溢出；确认状态完整可读、完整身份可按需取得、多个相同错误仍指向各自位置。
- **布局变动保留原生交互语义。** 提交按钮移入完成区时，核对其表单关联和键盘提交，不只测试鼠标点击；候选曾因位置调整丢失关联。用同一业务记录同时打开两个实例，确保标签、字段和提交各属自己的表单；实例唯一 ID 不改变业务身份或提交字段。
- **可读性修复不能取消规模保护。** 真实长身份、窄屏与大数据同时测；本轮候选关闭虚拟化后在 2,000 节点下全量渲染 2,003 项，说明内容与布局改善还须保留原有性能边界。无障碍详情的展开标记、实际点击框和键盘可达性也分别检查。
- **改主动作时测试跨阶段手势。** 检查变发布的候选曾让双击或持续 Enter 跨过独立决定。覆盖快速完成、重复按键、后续点击及释放后重新激活；前一阶段的手势不得授权后一阶段。此为候选引入的回归，不反推原基线已有此缺陷。
- **把删掉的叙述与保留的能力列成对照。** 零／一／多关联、必填项、错误、关键披露和相邻独立查看场景分别复核；公共组件不能因一个上下文去重而丢掉其他场景必需的信息。
- **分开记录原发现与候选回归。** 保留发现层次、受影响版本和最终冻结源；候选有修订不等于集成验收通过，自动化或专家截图审查不替代真人理解证据。

### 产品模型最小工作表

| 要写清的内容 | 本轮应用示例（不是通用强制架构） |
|---|---|
| 对象及关系 | 一个 Profile 对零到多个独立 Output；统一工作台不把一对多改成一对一。 |
| 稳定身份与影响范围 | 编辑 Profile 与发布某个 Output 是不同动作；其他 Output 的冻结产物、凭据及发布时间不应被更新。 |
| 权限和数据权威 | 来源/集合计算使用既有租户权限与后端预览；不能前端重写处理引擎，不能将展示用脱敏节点回写为凭据。 |
| 转换和独立保存边界 | “添加并使用”可独立保存来源，再加入当前未保存配置；不等于配置已保存或订阅已发布。 |
| 结果归属与生命周期 | 发布后获取链接的状态必须活到任务完成；成功导致列表/父组件重渲染时，不应卸载唯一的结果入口。 |
| 冻结与工作副本 | 已发布摘要来自发布时冻结数据；当前草稿不是历史发布内容，旧产物摘要缺失不能用当前配置补猜。 |
| 计划与观察 | 路线保存、授权、凭据准备、排队、应用和确认生效分别取证；未知不合成绿色“就绪”。 |
| 上下文与确认 | 批量动作带入对象/策略/范围；减少重复重选，但不默认扩大范围或省略危险后果确认。 |

### 内部严重性示例

- **P0**：错误对象变更、误报部署成功、丢失输入/配置、必需操作无法访问；立即优先评估具体后果。
- **P1**：常用任务明显受阻、范围不清、恢复困难或核心信息不可读。
- **P2**：非阻塞的层级/一致性/装饰问题。按影响调整，不仅按视觉显眼程度排序。

可访问性问题的风险取决于受影响用户和任务；P0/P1/P2 不等于 WCAG A/AA/AAA。

## 3. 十二项可复用验收标准

以下操作测试是**项目综合方法**，来源仅解释理由；每次新审查默认 UNVERIFIED。

| ID / 标准 | 来源 | 所需运行界面证据 |
|---|---|---|
| UX-01 明确作用范围 | GS-04、05 | 工作空间/环境/对象身份可识别；用两个可区分范围切换，确认内容及动作目标同步，无静默跨范围操作。 |
| UX-02 按任务统一导航 | GS-05、02、14 | 完成观察→检查→配置→验证，无需选择能力模式，也不丢失对象；名称描述目的地而非内部模块。GS-14 只借鉴任务分组，不采用其模式分裂。 |
| UX-03 单界面渐进披露 | GS-06、07、08 | 决策关键内容可见，次要详情/帮助可展开；必填项与错误不埋在关闭区域；鼠标和键盘均可完成。 |
| UX-04 清晰页面/动作层级 | GS-03、02、13 | 区分页面标题/主操作/表格工具/行操作；例如创建属于页面，筛选作用于列表；同时检查视觉和语义标题。社区检查表仅辅助。 |
| UX-05 支持判断的表格 | GS-06 | 列支持比较，技术细节可查看；组合搜索/筛选/排序后，活动状态和结果正确、列名明确。 |
| UX-06 上下文批量操作 | GS-06 | 选择后显示相关动作及数量，取消选择正常退出；明示本页选中与所有匹配的区别，危险操作确认目标；跨页语义为项目附加要求。 |
| UX-07 连续性与真实反馈 | GS-09 | 保存的等待/成功/失败符合实际；详情返回恢复列表上下文；失败保留输入；toast 消失后仍能恢复。 |
| UX-08 区分空/错/未知 | GS-10 | 分别测试无资源、无匹配、权限失败、缺设置、后端不可用；下一步相关，不把未知显示为零或成功。 |
| UX-09 局部加载与恢复 | GS-11、09 | 初次结构有合适占位；局部动作不无故阻断其他工作；防重复提交；失败可恢复，不无限加载。 |
| UX-10 可理解的表单 | GS-07、08 | 标签、单位、示例、必填/可选约定一致；错误提供具体修正方式；服务端失败保留值。 |
| UX-11 键盘与辅助技术 | GS-01、08 | 不用鼠标完成创建/编辑/筛选/选择/恢复；检查焦点顺序、可见性、弹层返回焦点、可访问名称、帮助、错误/状态关联；测试真实组合而非组件演示。 |
| UX-12 自适应密度与可读性 | GS-01、12、02、13 | 调整视口和缩放，操作可达、文字可读；重排导航和筛选，宽表在容器内滚动而不撑破整页；实测对比度，不凭观感；不迁移框架。 |

## 4. WCAG 2.2 选定规范性检查

依据 GS-01，仅是**非穷尽的 A/AA 子集**，每条都需阅读定义与例外。完整符合性还需检查所有适用准则、完整页面和完整流程，不能声称此表覆盖全部 AA。

| 成功准则 | 检查要点 |
|---|---|
| [1.4.3 Contrast (Minimum)](https://www.w3.org/TR/WCAG22/#contrast-minimum) | 普通文字通常至少 4.5:1，符合定义的大字至少 3:1；按规定处理例外。 |
| [1.4.11 Non-text Contrast](https://www.w3.org/TR/WCAG22/#non-text-contrast) | 相关 UI/图形信息通常至少 3:1，注意适用条件和例外。 |
| [1.4.4 Resize Text](https://www.w3.org/TR/WCAG22/#resize-text) | 文字放大到 200% 不丢失内容/功能，遵循例外。 |
| [1.4.10 Reflow](https://www.w3.org/TR/WCAG22/#reflow) | 纵向内容按 320 CSS px 宽度检查重排；固有二维内容例外不豁免整页。 |
| [2.5.8 Target Size (Minimum)](https://www.w3.org/TR/WCAG22/#target-size-minimum) | 指针目标通常 24×24 CSS px；间距、等价、行内、用户代理、必要性例外需逐项判断。 |
| [2.1.1 Keyboard](https://www.w3.org/TR/WCAG22/#keyboard) / [2.1.2 No Keyboard Trap](https://www.w3.org/TR/WCAG22/#no-keyboard-trap) | 键盘可操作且无焦点陷阱。 |
| [2.4.3 Focus Order](https://www.w3.org/TR/WCAG22/#focus-order) / [2.4.7 Focus Visible](https://www.w3.org/TR/WCAG22/#focus-visible) / [2.4.11 Focus Not Obscured](https://www.w3.org/TR/WCAG22/#focus-not-obscured-minimum) | 顺序合理、焦点可见，不被作者创建的内容完全遮住。 |
| [1.3.1](https://www.w3.org/TR/WCAG22/#info-and-relationships)、[3.3.1](https://www.w3.org/TR/WCAG22/#error-identification)–[3.3.3](https://www.w3.org/TR/WCAG22/#error-suggestion)、[4.1.2](https://www.w3.org/TR/WCAG22/#name-role-value)–[4.1.3](https://www.w3.org/TR/WCAG22/#status-messages) | 信息关系、标签/说明、错误识别与建议、名称/角色/值及状态宣告；检查实际程序化关联。 |

自动测试超时应记录退出状态/日志，并先诊断资源、测试隔离和真实行为；未完成不是通过，也不能未经调查直接归因产品缺陷。记录实际观察时间，后续结果以追加记录更新，保留原失败证据。

证据不得包含密钥、客户数据或私有参考 HTML。来源研究不授权更改账号、安装脚本、破坏性测试或生产部署。私有预览须经正常授权登录；登录不可用时保留阻塞。

## 6. 可迁移的研究发现（不是产品缺陷断言）

- 跨模块的完整任务比永久基本/高级分裂更符合本次需求（GS-05）。
- 详情/帮助适合渐进披露，必要表单信息不适合隐藏（GS-06–08）。
- 通知应帮助完成任务，关键恢复路径不能只存在于短暂 toast（GS-09）。
- 空、不可用、零是三种不同语义（GS-10）。
- 有来源的视觉建议仍需真实测量与任务测试（GS-01–02）。

## 7. 2026-10-22 产品建模复盘：发现 → 原则 → 复测目标

以下是本轮审查与实施过程发现，区别于第 6 节的通用研究启发；当前只沉淀方法，不签收最终修复。详细身份/HTTP 合同以[实施规格](PRODUCT-EXPERIENCE-MODEL-2026-10-22.md)为准。

| 真实问题 | 不能只做的表面修补 | 可复用原则与具体复测 |
|---|---|---|
| 同一配置从不同入口进入，发布可能变成更新或新建 | 只统一按钮文案或减少导航项 | 发布意图显式建模；一配置两链接从各入口进入，更新指定一个，不新增或覆盖另一个；保存草稿不等于发布。UX-01/02/07；GS-04/05/09。 |
| 从来源快照汇总原始节点，冒充集合整理后的可选结果 | 把“原始节点”改名为“最终节点” | 使用权威处理预览，列表与策略组选项共享最终结果；过滤/重命名/去重、迟到响应、失败均测试，不以原始结果兜底。UX-05/07/08；GS-06/09/10。 |
| 发布成功后，取链接的局部状态随组件卸载消失 | 多显示一次成功 toast | 状态所有权覆盖任务寿命；成功引发父列表更新后仍可获取同一 Output 的结果，关闭后仍有持久入口。UX-07；GS-09。 |

## 8. 真实后端走查的两项补充方法（2026-10-22）

这两项来自真实浏览器与 Go 后端任务走查，而非只读 mock。它们说明“数据保存正确”和“用户得到正确反馈”仍需分别验证；修正与完整验收分别见[UX23验收记录](../verification/UX-STATE-EDITOR-2026-10-23.md)，局部闭环不抵消整套失败。

### 8.1 缓存依赖和 checking 状态属于业务模型

发现：保存草稿后冻结发布内容保持正确，但 overview 的比较结果仍受 15 秒缓存影响，错误声称与当前草稿一致。错误不是后端把草稿自动发布，而是界面继续展示已失效的判断。

复用方法：

- 每个派生状态记录**依赖对象、证据版本/输入范围、失效事件与再计算状态**。保存配置、接受来源更新或改变集合后，相关比较证据必须失效，不能只刷新编辑器本身。
- 将 `checking`、失败、不可比较与已确认一致分开。旧比较值可以作为注明时间的历史信息，但不得以当前肯定状态展示。
- 写后立即回到总览/其他入口，验证“重新检查→最新比较”，同时确认冻结发布未被改变。不同输出可能有不同候选，失效范围按真实依赖定义，不擅自更新兄弟 Output。
- **不得让测试睡过 TTL 再检查**来掩盖错误反馈；测试在写后用户实际可见时点断言，观察检查中及终态。等待应针对真实请求/界面状态，而非凑缓存过期时间。

关联 UX-01、07–09；来源 GS-09（真实反馈）、GS-10（未知与空的区别）、GS-11（加载状态）。具体缓存依赖模型是本项目方法，不是上述来源对本系统的实现要求。

### 8.2 原生历史导航必须以真实浏览器验证

发现：改名后直接使用浏览器 Back，草稿丢失且没有放弃确认；只派发 `hashchange` 的单元测试未覆盖真实 history 行为。

复用方法：

- 区分页面内导航、深链、`hashchange`、`popstate`、原生 Back/Forward 和刷新/关闭；一个合成事件通过不能代表这些路径都正确。
- 真实浏览器执行“编辑→Back→继续编辑”，检查 URL/当前对象/输入/焦点；再执行明确放弃和 Forward，确认历史位置与对象一致且无循环跳转。
- 脏状态覆盖文本缓冲、字段改名及未应用 JSON；内部切换和原生历史共享相同的用户决定，但保留各自正确的事件合同。
- 继续编辑必须真实保留值，而不只检查确认框出现；明确放弃后只丢弃授权的草稿，不误撤销已独立保存来源。

关联 UX-02、07、10、11；GS-07、08、09。真实浏览器修复复测不能由更多同类单元测试数量替代。

### 8.3 从有界成功到完整验收

已走通的“选择一个目标更新”“来源失败恢复”“无效 JSON 恢复”只证明对应任务、数据和构建。新增链接→检查发布→获取链接仍须走到最终结果，不能在成功 toast 或服务端响应处提前结束。每次报告列出实际后端类型、对象对照、操作与不变量，不以测试数量作为易用性证据；不在方法文档暴露凭据、私有 HTML 或含敏感数据的 trace。


## 9. 可达不等于可发现：稳定截图中的决策层级（2026-10-22）

真实运行界面的稳定截图审查发现：更新发布审阅默认展开大段技术 JSON，1280×960 视口仍看不到最终确认。自动化能够滚动定位并点击，只证明按钮可达，不能证明用户容易识别下一步。

- 审阅先展示**明确目标、语义变更、影响范围、风险与确认动作**；完整技术详情按需展开，保留全部配置能力，而非删除技术内容来缩短页面。
- 以实际视口下的默认状态检查：用户在不理解内部格式时能否判断影响和下一步；技术详情展开后仍有合理的回到确认路径。
- 浏览器动作断言与截图层级审查分别记录。不要把 `scrollIntoView` 成功等同主操作可发现，也不一概要求所有确认始终固定或无滚动。

另一项发现：已在有效 Profile 上下文明确选择“新增第二链接”，流程仍要求重复选择同一 Profile 并继续。这是冗余决策，不是必要的风险确认。

- 可信且仍有效的对象上下文应直接传递；用户可理解当前归属，必要时显式更换。范围失效/无权/不明时才要求重新选择。
- **删重复选择，不删发布后果确认**：新链接目标、输出方式、独立身份、将新增而非更新等决定仍应明确；不要因简化入口而默认复制 Profile 或覆盖现有链接。
- 验收以用户要重新理解/决定什么为单位，而不是只比较点击数。

关联 UX-01/03/04/07；GS-03（关键动作层级）、GS-06–08（分组与渐进披露边界）、GS-09（任务反馈）。这是基于本轮审查形成的项目方法，不是来源作者对具体页面布局的强制规定；修正效果需后续真实界面复测。


## 10. 两个容易漏掉的验收分支：接受放弃与真实触控尺寸

### 不只测试“取消保留”，也测试“接受后继续”

本轮出现过全局放弃已接受、局部编辑器仍保留而阻塞目标的双重守卫问题。方法上要把取消/接受视为同等重要的两条路径：

- 取消：原身份、完整 scope、输入和历史位置保持，不意外执行目标动作。
- 接受：只丢弃明确授权的草稿，解除旧编辑状态，**一次确认后完成原目标动作**；不能再弹第二次同意或留下隐形阻塞。
- 页面内导航、自然 Back/Forward、query-only 各按真实事件路径检查。全局和局部守卫要有唯一的决定所有权；不要靠清空 QueryClient 或全部应用状态消除编辑器。
- 本应用采用明确全局放弃时递增工作区 generation 卸载旧 editor；这是本项目实现选择，不是通用框架规范。四项回归先失败后通过，再有真实浏览器接受分支证据。

关联 UX-02/07/10/11；GS-07–09。测试数量不是任务可用性的替代物，断言应落在“动作实际继续、值/身份按决定变化”。

### 可见、可点击与舒适触摸分开测量

后续样式检查发现按钮可见但只有 24 px 高；“脚本能点”不能证明窄屏触摸舒适。两处发布 Modal 采用局部 flex/滚动 body 和两按钮最小 44 px，以实际 DOM 几何验证。

**44 px 是本项目舒适目标，不是 WCAG AA 统一要求。** GS-01 的 2.5.8 通常以 24×24 CSS px 及其例外检查，不能把更高产品标准写成该规范原文。验收分别记录目标实际宽高、相邻间距、header/footer、展开技术内容的可达性及页面溢出；默认/展开和桌面/窄屏分别检查。

业务 freeze 的完整任务与后续样式补测分开标记构建/变更范围：本轮 11 项业务任务之后另有 2 项 390×844 样式+关键业务断言，不能合并声称所有任务已在所有视口重跑。来源仍为 GS-01/03/07/12 与项目综合判断。

## 11. 从“正确可用”继续到“容易理解”

本轮在工程基线通过后再次检查真实截图，仍发现关系清单被重复概览压低、主要流量决定藏在另一标签页、审阅依靠用户记忆两份摘要。由此采用以下可复用循环，具体任务合同见[产品体验实施简报](PRODUCT-QUALITY-ITERATION-2026-10-22.md)：

1. 先写用户要找到的对象、要做的决定和期待的结果，再审查界面是否让这三件事直接可见。不要用更多帮助文字掩盖层级问题。
2. 沿真实对象关系组织一套界面；低频详情按需展开，不另建简单版/专业版。去掉重复决定时保留目标新鲜度与必要后果确认。
3. 验收必须有非零、有区别的数据。导入连接、选择流量去向、发布给某个客户端是三种不同意图，不能只以空配置取得链接证明首用体验。
4. 将证据分成源码判断、组件行为、真实后端任务、实际像素、代理启发式审查和真人无提示观察。每一层只支持自己的结论，不能相互冒充。
5. 按目标→信号→测量记录成功与失败；没有实际测量就不报告效率提升比例，没有人类观察就不声称用户一眼理解。先完成授权内的本地改进，不为补研究样本反复打断用户。

来源 GS-03/05–10/15；上述循环与本地停止条件是本项目综合方法。GS-15 是研究参考，不是认证。当前迭代的实施和复测状态另记，不从这份方法论推断已完成。

## 12. 动画不能重新初始化用户的业务决定

真实首用任务发现，用户已经输入客户端订阅名，弹窗的打开动画结束后却重新填入默认值，连带重置检查会话。等待动画后才在测试中输入会掩盖数据丢失，而不是修好体验。

- 默认值应在交互开始前按明确的新会话初始化；同一对象的背景刷新和迟到视觉回调不能覆盖用户输入、已检查内容或创建身份。
- 真正取消后重开、主动更换业务对象，与同一对象的新数据引用分开定义。前者可按合同新建会话，后者不能仅因对象引用变化重新初始化。
- 回归有意覆盖“开始输入→迟到打开回调”和“已经检查→同ID背景刷新”，断言值、目标和检查身份，而不只检查弹窗还在。
- 再以真实界面完成“自定义名称→检查→发布→取得同一命名的结果”。组件回调测试与真实首用闭环互补；不以固定等待掩盖时序问题。

本项目的绘制前、稳定配置ID初始化是具体实现，不是通用框架规范。关联 UX-02/07/10、GS-07–09；问题与分层证据见 UX-I27。

## 13. 在容器任务中取得引用对象，而不混淆保存边界

[集合任务审查](COLLECTION-TASK-REVIEW-2026-10-22.md)将“编辑集合时需要新来源”作为一条连续任务，而非两个菜单的独立操作。以下是本项目方法；具体修复状态和冻结证据另记。

1. **先确定父草稿的所有权。** 进入子任务前列出须保留的名称、稳定身份、有序引用、逐来源处理及合并后处理。单一可见任务不等于销毁父草稿；返回不能依赖重新读取尚未保存的集合。
2. **用写入表区分持久化与引用。** 来源保存成功可独立存在；只有符合当前使用条件的来源才加入父草稿。父草稿保存、配置保存、订阅发布各有自己的明确决定。取消父任务不撤销已成功的独立写入，重试读取也不重发该写入。
3. **分别走就绪与诊断分支。** 已保存不等于已接受或可用。候选／诊断结果应保留真实问题和恢复入口，不为连续性自动接受。2026-10-22记录中的诊断需经离开守卫前往既有来源页，取消导航保留草稿；那是受保护的外部恢复路径，不是完整就地恢复。2026-10-23真实首导入分支证明它仍打断常规任务，现按第14节拟定就地审查合同；此处不签收候选修复。
4. **核对中仍保留可信身份。** 刚成功创建所得的稳定 ID、名称与权威列表的新鲜度分别建模；延迟／失败的重新读取不能把已知对象变成无名引用，也不能让旧展示信息冒充最新状态。覆盖立即返回、延迟读取和读取失败，而不是等列表刷新完才断言。
5. **按真实状态验收控制权。** 子任务的干净、已修改、提交中、失败分别测试取消和离开；父任务仍有未保存内容时继续受守卫保护。返回后检查可见任务、值、顺序及触发入口焦点，包含动画结束后的自然状态，不以强行聚焦替代实际结果。
6. **渐进披露需要可理解的摘要。** 收起时说明处理用途和非零配置数；停用步骤仍计入配置数，但不宣称执行。展开、重排、再收起和保存后重开分别核对步骤归属及两层顺序。
7. **异常布局与功能分开验收。** 320 px 错误正文被恢复按钮挤窄，即使没有水平溢出、动作可用，仍是可读性问题。检查正常／诊断／读取失败的实际像素、恢复动作与焦点；记录候选新增回归，不倒推为原产品缺陷。

关联 UX-01–04、07–12；沿用 GS-05/07–12/16/21 的来源及访问记录。以上对象所有权、保存边界、即时身份保留和复测矩阵均为项目综合方法，不是来源作者对本产品的实现规定。完整自动化、选定截图启发式审查和真人理解证据仍分别报告。


## 14. 2026-10-23 从相同画面 不同结果中发现隐藏状态

本节是本轮实证形成的项目方法，不是新规范或修复完成记录。具体发现、证据强度和待完成验收见[真实状态与编辑任务审查](UX-STATE-AND-EDITOR-REVIEW-2026-10-23.md)；官方依据与2026-10-23访问记录见[来源目录](UX-GUIDELINE-SOURCES.md)。沿用UX-01/03/07–12，不另造一套评分框架。

1. **对相同画面做语义对照。** 在同一有效输入下，用不同编辑路径得到看似相同的状态，再比较权威输出。F1中清空地区与清空来源分别产生缺省和`{}`，实际成员1→2→1。可见配置必须明确“关闭／全部纳入／条件纳入”；开启时清空条件不关闭规则，只有显式关闭才能关闭。全部指当前配置物化后的有效连接，不是库存或自动发布。
2. **用真实支持输入探索分支。** 不只给成功样例或注入错误。完整Mihomo/sing-box配置真实产生首导入候选，证明候选审查属于受支持任务；不能无频率数据就称“罕见”。父草稿在子任务中保留，候选需明确接受，取消/拒绝/稍后均不得暗中附加、保存父对象或发布。
3. **把HTTP结果拆成持久化事实。** 写清本地未保存输入、来源已持久化定义、已接受快照、指定Output冻结发布物。失败响应可能已保存部分事实，422不能统一译成未保存；未知结果先核对，不凭失败提示推断未提交。保存基线来自本次已确认提交载荷，不是脱敏字段；取消不能假装回滚已确认写入。
4. **每个键盘手势只执行其目标动作。** 从自然Tab顺序测试披露、排序、删除；Enter/Space分别验证，无祖先事件串扰，重排后仍属同一稳定对象。APG提供模式建议；组件库演示、点击测试或强行focus均不证明实际键盘组合已通过。
5. **活动控件不因业务停用而被整体淡化。** 停用处理仍可编辑时，禁止以整个编辑器opacity表现状态。先保留文字、控件和焦点可读性，再用必要状态表达是否执行。测真实计算颜色与祖先合成；不为了套用inactive例外削弱编辑能力。
6. **触摸尺寸与扫读共同验收。** 320px下先读普通步骤名，再检查长名和操作簇。放大按钮须伴随重排，不能把标题挤成单字列。实际命中区、间距、焦点和像素各自取证；44px是舒适目标，SC 2.5.8独立判定，无溢出不代表好读。
7. **无替代项必须由权威数据证明。** 只有成功、当前且确认零关联目标、无不可用指定目标时才直达新建表单；加载/暂停/错误/旧缓存不能当零。既有与已撤销目标仍按实际身份处理。删掉唯一单选门槛，不删除检查、独立新链接后果或最后发布决定；测试迟到读取与跨阶段重复手势。

### 本轮对证据记录的补充

对每个问题保留两条独立时间线：原发现及其基线；候选修改、候选新增回归、最终集成复测。一次审查脚本退出0可能只表示成功采集了缺陷，不表示产品通过。历史656项Web/48项浏览器是上一构建的有界证据，既不被新发现抹掉，也不签收新修复。

## 15. 整合失败如何转化为方法 而不是放宽验收

2026-10-23同轮增补。原问题的针对性修复已有实际验证，但首次完整运行仍有19项Web和17项浏览器失败，第二次仍有26项Web和5项浏览器失败，第三次built本地lane仍有17项Web、3个未捕获异常和2项浏览器失败。以下方法来自逐项诊断与有界修订；[验收记录与可携带case索引](../verification/UX-STATE-EDITOR-2026-10-23.md)保留四次非全绿结果、局部结果和有边界的产品接受，不把接受等同工程全过。不把测试迁移、产品修复、未复现和未运行混为“已解决”。

### 交互结束要验证生命周期

隐藏不是销毁，也不自动代表退出交互。菜单关闭后可能还有缓存节点和迟到聚焦；只断言不可见或`aria-expanded=false`不够。本轮来源菜单的合同是关闭即卸载菜单内容，再按关闭原因处理焦点：Escape返回同一持久入口，指针点到别处不抢焦点，选择动作交给既有确认而非提前执行。实际节点、焦点事件与下一帧结果共同取证；不从错误截图补猜未记录的时序。

这是该菜单的生命周期合同，不要求所有折叠内容销毁。富编辑器可以保留关闭内容与草稿；要检查隐藏内容是否仍参与不应发生的交互。APG菜单指导解释键盘预期，不规定本项目的React缓存解法（GS-25）。

### 动作名称稳定 状态另有表达

动作在等待前、中、后仍是同一动作时，可访问名称应保持任务意义，与可见文字一致；装饰性loading图标不能挤进名称，忙碌和禁用分别用恰当状态表达。优先正确原生标签/命名关系，不把`aria-label`当普遍补丁，也不放宽测试名称匹配去掩盖真实污染。

SC 2.5.3关注可访问名称包含可见标签，并不禁止一切附加文字；名称含“loading”不自动等于该条失败。稳定命名是本项目质量合同，需核对实际可访问树及各阶段的操作/状态（GS-01、26）。

### 正确分支从首次有效渲染开始

权威数据已就绪且满足零目标条件时，直接渲染目标表单，不先插入旧门槛再靠副作用切走。进入后仍由稳定编辑会话保存输入，不让背景读取重置草稿。测试同时检查过渡DOM、最终可见状态、键盘顺序和无自动写入；DOM插入证据不冒充拍到闪烁。数据尚未就绪则保留真实加载/失败/暂停，不抢先推断零（UX23-C04）。

### 聚合诊断保留含义与隐私边界

先按已知语义判断哪些诊断可以合并，再核对事实、原位置、数量单位与下一步。两条提取警告可以共享一张卡，但计数是诊断记录数，不是推测被忽略节点数。未知代码不能被硬套成同一排除原因，也不能假造后端未提供的严重性。

压缩重复不授权增加原始消息展示。已知代码已有安全摘要时继续使用；不能为“保留详情”重新暴露不受信任消息中的地址凭据或其他秘密。写正向事实/索引断言，同时用合成敏感串做负向披露断言。保留未知诊断的既有路径不等于已证明通用脱敏。隐私边界属于本项目合同，不因减小卡片而削弱（UX23-C06）。

### 既有可用版本与新导入就绪不是同一判定

已有来源的选择要同时表达身份与适用状态，不能只显示名字、到保存才用匿名错误让用户找对象。恢复入口应带回具体稳定身份，在原父草稿内修正；Profile经Collection间接引用时仍保留输入模式、引用顺序与全部配方，不擅自展开成直接来源或重建集合。

可用性、最新处理结果和待接受候选分开建模：enabled且已有接受快照（包括接受的空快照）允许使用旧版本，最新失败/待审候选不自动撤销这一事实。新导入任务为“本次结果已就绪”采用的保守条件，不能直接套到既有来源选择上。暂停/无接受快照须可识别且可具名修复，读取未知不冒充不可用；不能静默过滤现有引用、启用来源、接受候选或保存父对象。移除最后引用时，还要明确清除与该引用关联的旧物化连接；不能把“当前未选择来源”误作“继续沿用历史派生值”。显式移除和取消修复是不同动作，不能自动删改共享Collection配方。正反两组数据、直接/间接路径及移除后权威结果都需实测（UX23-C10已在Q03最终14px构建有界复测，整体仍未通过）。

对可信422的重复反馈，也先确认不同消息是否承担独立事实：保存状态、导入失败原因、旧快照后果、下一步是否都还在。只删除已被准确覆盖的generic错误；未知422/503/409以及结果不明的历史必须保留，不能为了中文整洁而吞掉不确定性（UX23-C09在最终构建有界通过，整体门槛另列）。这些是现有来源合同的修复，不扩成新的状态框架。

### 每步响应与完整任务总预算分别测量

一次总时限失败可能截断完整操作链，不能直接解释为某一步超过用户可接受延迟。先分离初始化、寻找/操作、请求、提交、清理和总时长；DOM模拟器的样式计算与真实浏览器交互不是同一性能证据。清理问题、测试操作方式、产品等待和调度假设须分别验证，不能用一个孤立通过确诊根因。

完整格式通常以粘贴输入，可以采用真实点击和粘贴，但仍保留短字段输入、字段顺序、失败保留和最终业务断言；没有逐字输入的慢任务不能借此删操作。若需诊断更长任务，可在明确授权的隔离观察中记录总预算调整，保持步内等待与自然操作不变；该观察不是原预算通过，也不自动进入正式门槛。未经测量和批准，不加全局超时、固定sleep、强制点击或重试直到绿。工具默认值不是产品延迟SLO（GS-27–29；UX23-C08）。

本轮预算证据分三层：受限来源多界面任务的10秒预算曾得原文件19/19；统一jsdom10秒/Node5秒政策随后以3项正向和5项预期deadline负向独立核对；Q03/Q04已按该政策完整运行，仍分别有4项/3项10秒test-body deadline；完整门槛未全通过。政策夹具进程exit1符合设计，但必须逐项核对准确状态/消息，不能仅凭exit1宣布负向通过，也不能把5项预期失败加入产品套件计数。步内1秒、显式短预算和钩子约束继续保留；这些证据不证明旧性能根因或用户延迟改善。

### 前置建立 可见稳定与运行方式分别记录

工作区建立可以包含会话确认、页面模块载入与首次React提交，不等于任务内某次保存。先标记失败发生在前置还是任务体，按实际产品边界制定有界前置预算；不能为修前置而一并放宽所有动作/断言。DOM中的main已出现也不代表懒加载业务模块就绪；等待真实导入结束属于前置，随后字段/焦点的短断言仍须执行，不改成长期等待字段出现。HTTP返回、响应消费、提交与可见性分别取证，终态截图不追认截止时的状态。

稳定性检查针对正在操作的可见表面。隐藏装饰spinner仍有动画，不必然意味着编辑器在移动或保存未完成；应同时看有效可见性、尺寸、祖先透明度、目标交互状态及布局采样。反面也要成立：真实可见移动/忙碌仍必须拦住，不能删掉整条稳定性断言。对象定位使用公开搜索/分页与稳定身份，不假设整套运行时清单只有当前夹具。

每份浏览器报告明确dev、built-frontend local real-backend或真实部署lane及实际源/配置。Vite preview服务本地构建产物，并非生产服务器（GS-30）；本地built lane通过不覆盖历史dev失败，不证明开发加载根因已修复，更不证明外部生产/流量。对照需要相同任务及明确的构建/环境差异，不能把换lane包装成产品修复。

### 迁移测试保留意图 隔离历史失败

- 旧标签、旧页面或组件私有类已被有效设计变更替代时，改用当前准确的公开动作、角色和关系；列出保留的隐私、焦点、取消与无隐式写入断言。
- 用有效的公开数据合同构造夹具，明确哪些响应被注入；信息性诊断不冒充失败，合成候选不冒充真实解析。真实可用性依赖enabled/已接受快照时，旧夹具只有名称/ID不再足够；修订GET响应须保持该case原有业务意图，不给产品加“缺字段默认可用”的捷径，也不削弱保存请求断言。
- 跨任务环境用进入时的完整对象基线比较，不能假设库存为空，也不能过滤未知对象或删除它们来过测试。副作用对照包括完整兄弟对象与冻结产物。
- 会话单项未复现、指针卡点原因不明、环境前置失败、聚焦通过及全套失败各保留自己的状态。HTTP头、后台写入、页面提交、实际点击完成分别取证。未捕获异常另列，不混进失败test数量，也不因相关文件的断言通过就忽略；报告关联的文件名不是确证根因或跨case污染。
- 生命周期强化与根因修复分开：等待既有清理在act边界完成，可以让恢复全局环境之前有明确顺序；不能用sleep、window补丁或忽略异常换取干净报告。若原同步清理在观察中也通过，就如实记录未复现，不补造RED→GREEN，也不声称已取消所有异步工作。
- 交付使用随包case ID、安全摘要和已审核附件；内部报告、trace、认证材料及响应正文不复制成公开方法文档。最终结果只对应同一冻结构建，不累计局部成功来替代完整验收。
- 若验收终态后才补齐文档，分别记录受测清单与交付清单，用明确的documentation-only hash bridge证明生产、测试、配置和构建输入逐字节不变。列明新增/修改文档，不把交付包全量hash变化误作代码复测；若任何受测输入变了，重新判断所需验收，不能借“只补文档”绕过。

技术诊断放在验收记录中；产品界面只表达真实动作、状态与必要后果，不增加测试预算、缓存机制或证据限制的小字。保持现有React/Ant Design、单一产品模型和明确发布边界。


### 产品接受与套件可靠性分别收敛

停止条件由用户要作的产品决定和剩余风险界定，不由“再跑一次也许会绿”决定。等待已启动整套的实际终态，区分确定的业务断言失败、前置失败、总时限及未捕获异常，再找缺少的高风险任务结果。优先用真实浏览器/权威结果核对最小缺口；不预设下一轮全套，也不删断言或反复重跑直到绿。

若核心及恢复/身份任务有实际证据、已确认高影响缺口关闭、未发现确认的产品缺陷，可作有边界的本地UX接受，同时单列套件可靠性未通过与未知原因。这不是把超时判作环境或无害，也不是用浏览器通过证明DOM所有逻辑正确。出现业务不变量破坏、错误目标写入、丢草稿或明确产品缺陷时仍需闭环，不能借双轴判断绕过。每项结论写清适用对象、所需证据、剩余风险和停止依据；这些是项目决策方法，不是Google/W3C的验收规则。


调度机制断言与真实用户后果也要分层。一个DOM case若只在layout提交时读取dirty登记，并没有实际Back/unload，超时就不等于已看到用户丢稿；浏览器的取消Back保值、明确放弃和Forward完整性则验证用户后果，但不构成精确pre-passive窗口的形式证明。保留两类证据及各自失败，不为了签收把机制检查删掉，也不因局部调度检查未完成就重复新增已覆盖的整条旅程。


## 16. 持续打磨：沿着用户任务发现模型与反馈的断点

关联[2026-10-23持续审查](CONTINUOUS-UX-REVIEW-2026-10-23.md)及GS-09、16、31–33。以下是本项目的方法归纳，不是外部认证。

1. **先定真实任务，再看组件。** 例如导入来源、设置域名例外、给两台设备发布、替换失效节点、只更新一台设备。单个控件漂亮或可点击不意味着任务连续。
2. **把用户要判断的事实写成对象关系。** 规则匹配什么、流量去向是什么、这份内容属于哪个已发布订阅、影响哪台设备。数组顺序、数量和时间不能代替这些关系。
3. **分别验证已保存、已发布、已检查与实际应用。** 它们可以同时处于不同状态。不把最近检查当成持续同步，也不用最新草稿重建历史发布。
4. **遇到错误先判断下一步是否正确。** 明确缺失引用应提供修复入口；瞬时读取失败才用重试。相同名称不授权自动替换身份。取消与失败必须保留上下文和已有输入。
5. **检查变化的范围而不只看结果值。** 确认一台设备改变时，另一台的完整记录、访问身份和产物应保持不变；保留未修改分支不能仅靠相同数量证明。
6. **选择反馈必须看真实点击与时间。** 在反馈出现前、期间、结束后检查命中区、焦点、状态含义及布局稳定性。截图没有溢出、按钮尺寸够大，都不保证透明覆盖层不拦截点击。
7. **用能复现问题的证据做修正。** 来源、设计推断、公开界面复现、候选实现、整合复测分别记录。阴性对照或先失败后通过用于证明检查敏感，不把未复现问题臆断为性能故障已修。
8. **一次阶段完成只是继续探索的起点。** 保留明确已知缺口，继续同一任务链与相关普通场景。停止条件来自用户目标与已确认范围，不能用自定“有界通过”替代用户要求。

优先顺序：误导真实含义或丢输入的错误 → 无法完成/恢复的任务 → 重复认知与操作成本 → 视觉细节。结构能表达的内容不增加解释，必要状态/后果不为了简洁而隐藏。

### 长任务的恢复位置与焦点归属

以下是 Fleet / SessionBoundary 实际任务观察形成的**项目综合方法**。来源原则沿用[GS 来源登记](UX-GUIDELINE-SOURCES.md)中 GS-07/09（表单与反馈）、GS-16/21（内容与就近帮助）、GS-01/24–26（可访问性、焦点与命名）的原核验记录；本次未重新核验外部来源，具体布局与恢复合同不冒称官方要求。

- **错误跟随能解决它的动作。** 长表单页首有错误，不等于用户在末尾执行动作旁能看见。按恢复阶段选择单一位置：预览错误在预览旁；保留审阅的创建错误在创建旁；审阅失效、必须重做预览时回到预览旁。不要复制同一错误，也不要把按钮可用误当任务成功。此轮改善位置与关联，不证明所有错误内容均已本地化；受控夹具中的英文不代表生产文案修复。
- **几何入视口不等于可读。** 在实际滚动位置同时审阅状态、动作与阅读余量，不能只断言最后一个像素没越过视口底边。pending 状态的局部 8px 留白是具体布局选择，不是 WCAG 固定边距、通用规范或真人理解证明；不同状态仍需分别看图。
- **主动关闭不是再次抢焦点的授权。** 操作未完成时，如果允许关闭审阅层，必须保留诚实状态与恢复入口；迟到结果不借“显示反馈”夺回用户已选择的焦点。任务内必要恢复与关闭后的不打断分开验证。
- **区分浏览器边界与应用丢焦点。** 单凭 `document.hasFocus() === false` 不能判定应用焦点陷阱；用普通组件及原生对话框对照。浏览器边界相同，不排除返回页面后会话复核使工作区 inert、丢失原任务所有者这一独立应用问题。继承组件的瞬时背景焦点事件也须保留限制，不据稳定终态宣称原生等价或完整符合性。
- **恢复精确归属，不猜下一焦点。** 接续已确认的键盘离开时，仅恢复同一工作区、账户/会话世代中仍有效的具体控件；新焦点、身份变化或控件失效撤销恢复。DOM 覆盖与实际浏览器事件证据分别成立，不互相冒充；不以禁用会话校验或全局焦点历史换取连续性。

本轮决定、证据层次与保留限制见 [Fleet 恢复反馈与同会话焦点连续性](FLEET-RECOVERY-FOCUS-2026-10-23.md)；失败历史只在对应证据中维护，不在方法页复制。

### 类型化反馈与展开说明

- **稳定原因 → 诚实状态 → 安全下一步。** 以稳定的类型化原因表达后果与恢复，不能按英文 detail 子串或仅凭 HTTP 状态码翻译业务含义。未识别原因保留诚实未知回退；已经排队或被新操作取代，不得写成“未提交”或“可安全重试”。文案承诺以权威结果为界，不把技术失败直接改写为业务未发生。

### 先区分被动通知与任务恢复摘要

依据[来源登记](UX-GUIDELINE-SOURCES.md) GS-38–40，以下为**项目综合方法**，不是所有错误统一聚焦的规定。

- **先决定反馈是否需要交接，再选择角色。** 被动状态/alert不主动抢焦点；明确操作失败、需要回到当前任务恢复位置时，由该操作的唯一当前拥有者安排摘要交接。不要为聚焦内联错误新增alertdialog或模态框。

### 打开记录的基线与确认后的票据分别保护

依据[来源登记](UX-GUIDELINE-SOURCES.md)GS-41/42，以下是**项目适配**，不是HTTP If-Match/AIP154符合性声明。

- **先确定整条记录是否仍是打开时那一条内容。** 打开时取得实际记录、存在性和不透明内容token；在同一写事务中核对后才模拟候选。预览时才生成的票据不能倒推保护更早的打开快照。原记录缺失与投影生成的默认值必须分开；相同内容重新写入/重建可等价，不冒称检测每次写入或实例身份。
- **随后保护已审阅的决定。** 打开基线、预览→应用票据及本地请求/意图计数各有边界。token不授权；已有权限、预算、周期和准确候选检查继续执行。保留显式旧API全量替换兼容，不让新界面因缺少版本静默降级。
- **冲突恢复不等于刷新token。** 保留旧草稿；最新记录先独立展示，明确接受后才同时替换编辑值和基线。保留副本必须匹配自己的历史基线与完整、实际归表单拥有的设置，不能借用后来版本作“之前”，也不许冒称保留了控件私有缓冲区；成功保存要丢弃副本时，在该决定的确认中说明，失败/未知结果不丢弃。
- **记录变化与当前生效影响分开。** 用同一预览快照的完整类型化before/after审阅资源，即使没有受影响用户或当前账号周期不变。类型化快照不宣称原始JSON字节保真；隐藏但支持的值保留，未知字段失败关闭。
- **不同证据只回答自己的问题。** 旧公开API的实际覆盖示踪才复现缺陷，缺新接口/编译失败不是行为RED。后端原子性、DOM操作、真实本地流程和逐张像素分别记录；CSS残余可作小型真实补测，不重跑无关写入也不把旧流程改称新CSS全流程通过。焦点属于外层摘要时，视觉指示可以画在其直接子视觉框上，但被动alert不因此获得焦点；计算样式不能代替四边实际可见性。

### 当前确认层的键盘边界与可见绘制分开修复

[授权确认键盘记录](../verification/POLICY-MODAL-KEYBOARD-2026-10-25.md)形成以下**项目适配**；依据[GS-44](UX-GUIDELINE-SOURCES.md#2026-10-25-模态确认的局部键盘边界)及既有GS-01，不是通用焦点框架或符合性认证。

- **等待界面不等于服务端已提交。** 持有真实apply请求但尚未转发，可以验证pending控件和键盘；必须分别记录尝试、后端转发、结果与清理，不把前端等待测试当成应用成功或后端事务验证。


### 表单设置、未提交选择和不完整输入分别拥有

以下为[个人授权公开控件与编辑任务](../verification/ENTITLEMENT-POLICY-EDIT-2026-10-25.md)形成的**项目观察**，不是新通用编辑框架，也不是安装组件的所有版本或原生输入法认证。

- **先确认可观察的状态，再承诺保留。** 完整Form包含隐藏覆盖值和未启用周期参数，但不等于日期面板的临时选择或数字控件私有文本。个人编辑器使用这些控件的公开可选回调建立局部结算；Service/Group不因此获得同样的私有缓冲区保证。
- **结算动作不能偷带提交。** 用动作开始时的待结算状态与处理时状态共同核对，避免一次点击先关闭日期面板、再用旧值预览。未完成数字不能因blur恢复旧数值就被当作用户已同意；明确修复或丢弃后再重试。不靠自动确认、全局监听或序列化组件私有对象补救。
- **控制值身份和保存字节是两回事。** 未改变的日期字符串保持稳定的受控值投影，避免父级状态通知重置临时选择；未编辑值不重新格式化。刻意提交日期时，遵循已核对的现有组件精度，不为满足错误期望改计费时间或放宽原值保留。
- **区域拥有关系不能凭视觉相邻推断。** 位于Form外的重置原因不归Form焦点处理器拥有；新增明确的物理区域后，只揭示已经聚焦的原生控件并拒绝外部portal。该新区域明确复用保守整像素位移；前述Modal阶段的历史范围与原Service/Form默认算术不被改写，也不变成整个Drawer控件的认证。
